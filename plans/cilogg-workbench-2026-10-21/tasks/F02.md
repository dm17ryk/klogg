# F02 — Versioned format/profile registry and explainable bounded detection

**Read first:** [product specification](../00-product-spec.md), [execution guide](../MASTER_GUIDE.md), and the shared contracts in [02-data.md](../02-data.md). Execute only this task or its recorded independently reviewable slice.


**Integrated hard dependencies:** G01, G02, G03, F01. Capability-conditional dependencies described below are additional runtime gates; they do not reverse these edges.


**Purpose:** Reuse one selectable parsing profile across tables, charts, time lookup, exports and automation. **Depends on:** F01; P09 milestone. **Current anchors:** `src/CMakeLists.txt` currently has no logformat target; current previews/config imports live in `src/ui/{include,src}/{previewconfig,previewconfigparser,previewrepository,configurationexport}.*`, with schema `schemas/klogg-previews.schema.json`. Preserve those identities and adapters.

**Proposed files:** create `src/logformat/CMakeLists.txt`, `src/logformat/include/{logformatdefinition,logformatregistry,formatrecognition,formatprofilecodec}.h` and matching `src` implementations; `schemas/cilogg-formats-v1.schema.json`; `src/ui/include/formatprofiledock.h`, `src/ui/src/{formatprofiledock,mainwindowformats}.cpp`; tests `tests/unit/{logformatregistry,formatrecognition}_test.cpp`, `tests/ui/formatprofilewindow_test.cpp`. Modify `src/CMakeLists.txt`, UI/app build lists, Commander catalog/dispatch, configuration-export adapter and tests lists.

**Interfaces:** `DataResult<LogFormatDefinition> decodeFormatProfile(const QByteArray& json); DataResult<ProfileRevision> LogFormatRegistry::put(const LogFormatDefinition&,std::optional<quint64> expectedRevision); std::shared_ptr<const LogFormatDefinition> find(const QString& id,quint64 revision) const; DetectionReport recognize(const QVector<AnalysisLine>& sample,const RecognitionPolicy&,const LogFormatRegistry&);`. Profile contains UUID, schema version/revision, parser kind/options, ordered field declarations, timestamp/severity/body roles, multiline policy, sample assertions, filename hint and provenance. `RecognitionPolicy{maxLines=1000,maxDecodedBytes=4MiB,minMatchFraction=0.80,minWinnerMargin=0.10}`. Detection returns candidate scores, matched/failed lines, reasons and confidence label; filename extension is only a hint. An ambiguous tie stays plain text until the user selects a profile. Disabled detection performs zero scan reads.

- [ ] `F02_detection_is_bounded_and_explained`: 800/1,000 valid JSON rows plus 200 plain rows meets 0.80; 790/1,000 does not. Equal 0.90 candidates stay ambiguous; a 0.05 winning margin stays ambiguous; `maxDecodedBytes` stops reads at/below 4 MiB and reports sample coverage.
- [ ] `F02_manual_profile_survives_reopen_and_revisions`: explicit selection wins over detection; profile edit creates a new immutable revision, invalidates derived keys, and does not mutate a running job's frozen definition. Existing preview UUID/export round-trip remains byte/semantic compatible.
- [ ] Implement built-in/user/imported/plugin-declared profile sources with deterministic precedence and an inspectable diff/import error. Accept data-only parser declarations through the current supervised plugin manifests; do not load arbitrary native donor parser plugins. Unknown future versions remain retained/read-only or fail with a clear supported-version range.
- [ ] Add `list_formats`, `get_format`, `validate_format`, `put_format`, `detect_format`, `set_source_format`, `get_source_format` with schemas and revision conflict behavior. GUI choose/detect/edit/preview actions use these same operations; assert CLI/MCP/GUI candidate order, selected UUID, revision and parse diagnostics agree. Run focused and import/export/config regressions, then commit.

**Acceptance:** a mixed-source folder can keep a per-source profile choice; changing one profile does not reparse unrelated sources. **Rollback:** select plain text and disable recognition; retain versioned definitions without destructive downgrade. **Primary references:** [D1](https://github.com/64x-lunicorn/LogSquirl/blob/a88c4a4d1c701ab1dda528a5f284ee7d43d873e1/src/logformat/include/logformatdefinition.h), [D2](https://github.com/64x-lunicorn/LogSquirl/blob/a88c4a4d1c701ab1dda528a5f284ee7d43d873e1/src/logformat/include/formatrecognition.h), [R3](https://grafana.com/docs/loki/latest/query/log_queries/), [B3](https://github.com/dm17ryk/klogg/blob/bd74c338424845a2caac03d62fdff5187e7e8f0a/plans/log-analysis-roadmap.md). Donor recognition's 50-line/half-match defaults are evidence of one approach, not the chosen CILogg policy.
