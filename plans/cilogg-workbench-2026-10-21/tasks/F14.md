# F14 — Typed transform registry for advanced visual dataset shapes

**Read first:** [product specification](../00-product-spec.md), [execution guide](../MASTER_GUIDE.md), and the shared contracts in [02-data.md](../02-data.md). Execute only this task or its recorded independently reviewable slice.


**Integrated hard dependencies:** G01, G02, G03, F07, F08, F09, F10, F11. Capability-conditional dependencies described below are additional runtime gates; they do not reverse these edges.


**Purpose:** Let richer visualizations share the same query execution, limits and lineage without implementing calculations in UI widgets or browser scripts. **Depends on:** F07–F11; specialized algorithms land with the owning visualization task, after its input semantics are accepted. **Current anchors:** no advanced transform registry in baseline; P06's initial regex extraction remains a fast useful subset.

**Proposed files:** create `src/analysis/include/{datasettransform,datasettransformregistry,transformshapes}.h` and matching implementations; `tests/unit/datasettransformregistry_test.cpp`, `tests/ui/datasettransformparity_test.cpp`; schema `schemas/cilogg-transforms-v1.schema.json`. Concrete implementations later live in focused `src/analysis/src/transforms/` files, never in a renderer. The visualization plan owns shape-specific mapping/algorithm examples and tests, while this task owns execution/contract enforcement.

**Interfaces:** `class IDatasetTransform { virtual DataResult<DatasetSchema> plan(const DatasetSchema&,const TransformSpec&) const=0; virtual DataResult<DatasetDelta> consume(const DatasetDelta&,const TransformContext&)=0; virtual DataResult<DatasetDelta> finish(const CompletionContext&)=0; virtual TransformCapabilities capabilities() const=0; }; DataStatus DatasetTransformRegistry::registerTransform(const TransformDescriptor&,TransformFactory); DataResult<TransformPlan> compileTransform(const TransformSpec&,const DatasetSchema&) const;`. `TransformSpec{id,version,typedParameters}` is a QueryStage; descriptor fixes input/output schema roles, units, order/clock requirements, incremental/retraction/merge support and budget/lineage guarantees. Registration is application-owned code or data-only combinations, not arbitrary plugin code inside the GUI.

Initial reserved shapes: `hierarchy-v1` path+nonnegative/declared signed weight; `edge-flow-v1` from/to/weight and optional stage/series; `state-interval-v1` entity/state/start/end/unknown/coverage; `span-v1` trace/span/parent/start/duration/status; `cohort-v1` subject/start cohort/age-bin/eligible/outcome denominators; `funnel-v1` subject/stage/order/window/dropoff/eligibility; `profile-stack-v1` frame path/self weight/total weight/sample count. Numeric bin/2D-bin/category-pivot/topN+Other/Pareto transforms are F09 shared operators. Distinguish observed transition count from duration, flow from correlation, explicit span from inferred message grouping, and weighted profile samples from wall-clock runtime. No mapping invents missing domain facts. Each algorithm chooses exact ordering/tie/reset/gap/censoring rules, retraction support, limits and completeness before registration.

- [ ] `F14_transform_contract_is_typed_versioned_and_bounded`: unknown transform/version returns `unsupported_transform`; missing required role/wrong unit/incompatible clock rejects planning; shape rows cannot exceed current row/bucket/state budgets; failures retain prior published dataset revision and show stage-specific reason.
- [ ] `F14_registry_cannot_bypass_shared_execution`: two panels requesting the same transform share compatible scans/subplans; cancellation and child-worker regex limits remain effective; a transform declaring non-retractable returns `requires_rescan` on provisional replacement instead of accumulating wrong totals.
- [ ] `F14_each_registered_shape_has_source_lineage`: every emitted hierarchy/edge/state/span/cohort/profile row has a bounded source predicate/selector and explicit weight/denominator/exactness metadata; fixtures verify no output shape silently loses Missing/Unknown/partial status. Visualization-specific cards must add numerical input→output assertions before enabling each shape.
- [ ] Expose registry capabilities via `list_dataset_transforms`, `describe_dataset_transform`, `validate_query`, `query_dataset`, with the GUI builder showing only available compatible transforms. Assert identical schemas/results/errors through direct, CLI and MCP paths; commit the registry separately from specialized algorithms.

**Acceptance:** renderers consume typed rows, roles and lineage only. A missing transform disables its UI option with an actionable capability reason. **Rollback:** unregister one transform version and retain saved queries as unavailable/read-only; existing primitive queries/charts continue. **Primary references:** [R1](https://opentelemetry.io/docs/specs/otel/logs/data-model/), [R3](https://grafana.com/docs/loki/latest/query/log_queries/), [R10](https://grafana.com/docs/loki/latest/query/metric_queries/), [B2](https://github.com/dm17ryk/klogg/blob/bd74c338424845a2caac03d62fdff5187e7e8f0a/src/logdata/include/analysiscommands.h); shape semantics are CILogg design choices, not claims that these sources implement every listed transform.
