# F12 — Lookup enrichment, Value Names, and stable raw/display separation

**Read first:** [product specification](../00-product-spec.md), [execution guide](../MASTER_GUIDE.md), and the shared contracts in [02-data.md](../02-data.md). Execute only this task or its recorded independently reviewable slice.


**Integrated hard dependencies:** G01, G02, G03, F01, F02, F08, F10. Capability-conditional dependencies described below are additional runtime gates; they do not reverse these edges.


**Purpose:** Resolve codes, device IDs, severity, addresses and metadata consistently in tables/queries/charts without losing the logged value. **Depends on:** F01/F02/F08/F10; integrates P14. **Current anchors:** configuration/previews import-export adapters and raw/display separation; there is no Value Names module in checked master. Donor module paths are verified reference material, not already ported.

**Proposed files:** create `src/analysis/include/{lookupregistry,lookuptransform}.h` and matching implementations; new `src/valuenames/CMakeLists.txt`, `include/{valuenamesdefinition,valuenamesresolver}.h` and matching `src`; `src/ui/include/lookupeditordock.h`, matching implementation; `tests/unit/{lookupregistry,lookuptransform}_test.cpp`, `tests/ui/valuenamesdatasets_test.cpp`; schemas `cilogg-lookups-v1.schema.json` and fixture CSV/JSON tables.

**Interfaces:** `DataResult<LookupRevision> LookupRegistry::importTable(const LookupImportSpec&,QIODevice&); DataResult<LookupMatch> lookup(const LookupHandle&,const QVector<FieldValue>& key,const LookupPolicy&) const; DataResult<EventRecord> enrichEvent(const EventRecord&,const LookupBinding&,const LookupSnapshot&); DataResult<DisplayValue> ValueNamesResolver::resolve(const FieldValue&,const ValueNamesDefinition&) const;`. Lookup import fixes exact key types, column IDs, numeric base, case policy, locale and duplicate-key rule=`error|first|last|many`; default error. Null/missing/unknown keys do not coerce to empty/zero. Enrichment is a typed left lookup producing a separate declared field; many-match expansion requires explicit explode/caps. Default max100,000 imported rows /16MiB file and active-index budget8MiB, with visible limit. Imported revision is immutable and frozen in running queries.

Value Names is presentation: display label/tooltips can annotate raw codes while raw search/copy/export and query grouping remain raw by default. A query can explicitly group/filter on a named enrichment field; that includes lookup revision in the query key. Definitions and table indexes are shared with the enrichment transform rather than two incompatible key parsers. Unit mappings validate dimensions; labels never change numeric magnitude. Mapping changes invalidate presentation or enriched query caches selectively, not source byte indexes. Keep raw-to-display span maps for wrapped hit testing and selection.

- [ ] `F12_typed_lookup_never_changes_raw_keys`: numeric0, text"0", Missing, Null and empty text match their declared distinct policies; hex0x10 maps exactly to16 only under an explicit numeric-base column; duplicate imports default to `duplicate_lookup_key` and leave prior revision active.
- [ ] `F12_lookup_revision_is_frozen_and_left_joined`: unknown code remains raw with unknown-label status; failed enrichment retains source event; editing table rev1→rev2 changes newly run enrichment only, while the old job explains rev1. A many-match import cannot multiply rows unless explode is chosen and bounded.
- [ ] `F12_names_do_not_change_copy_filter_or_numeric_aggregation`: code2 displayed as"Busy" still sums/group-keys as2 unless the query names an enrichment output; raw copy retains original bytes/text; annotated export is explicit. Unicode/wrapped selections map correctly to raw spans.
- [ ] Add `list_lookups`, `validate_lookup`, `import_lookup`, `get_lookup`, `set_value_names`, `get_value_names` plus query lookup stage. GUI editor/preview, CLI/MCP import/conflict/unknown behavior and annotated state match; run configuration/raw-copy/render/query/export regressions, then commit.
