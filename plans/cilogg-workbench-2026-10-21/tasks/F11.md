# F11 — Compatible scan sharing, bounded multi-panel execution, and incremental live datasets

**Read first:** [product specification](../00-product-spec.md), [execution guide](../MASTER_GUIDE.md), and the shared contracts in [02-data.md](../02-data.md). Execute only this task or its recorded independently reviewable slice.


**Integrated hard dependencies:** G01, G02, G03, F07, F08, F09, F10. Capability-conditional dependencies described below are additional runtime gates; they do not reverse these edges.


**Purpose:** Let many panels reuse one decoded/parsed input pass while retaining independent queries, cancellation and correct append semantics. **Depends on:** F07–F10. **Current anchors:** one shared analysis scheduler/owner-thread lease registry, P03 backpressure/cancellation, P05 frozen manual rerun. Live dataset execution is new; do not silently turn existing P05 jobs into live jobs.

**Proposed files:** create `src/analysis/include/{datasetplanregistry,sharedscanplan,livetypedquery,liverevisionstore}.h` and matching implementations; `tests/unit/sharedscanplan_test.cpp`, `tests/ui/livedataset_test.cpp`; update `analysisjob.h`/`analysisjob.cpp` internally, dataset service and metrics. Use the same job registry/admission limits; a shared physical scan can fan out to several bounded consumers, each with a retained job/result descriptor.

**Interfaces:** `DataResult<SharedPlanHandle> DatasetPlanRegistry::attach(const ScanCompatibilityKey&,const QueryPlan&,const ConsumerBudget&); bool detachConsumer(const QString& jobId); DataResult<LiveUpdateResult> LiveTypedQuery::apply(const SourceUpdate&,const QVector<EventDelta>&); DataResult<DatasetRevisionHandle> publishRevision(const QString& jobId,const DatasetDelta&,const RevisionBudget&);`. `ScanCompatibilityKey` includes source identity/generation/frozen watermark or live frontier, encoding, exact physical/event scope, profile+assembly+time+alignment revisions, parse projection and worker backend/budget compatibility. Distinct selected scopes/policy versions do not share incompatible results. Common-subplan reuse includes parsed fields and common filter/projection; later reducer state remains per logical query. Compatibility checks must account for deadline and read/memory budget differences: sharing cannot grant a looser limit.

Fanout gives each consumer delivery credit; a stalled pane can detach/pause with explicit `consumer_backpressure` while others continue. Never wait for a GUI acknowledgement holding source locks. Active shared plans count toward scheduler concurrency and global state; hidden panels can pause consumption but cannot silently release another pane's job. Default update coalescing250ms; a live subscription has an explicit trailing event/time window and maximum retained points/keys/bytes. Subscriptions are bounded control handles (maximum8), not immortal running jobs: each scan/update epoch is a normal admitted job subject to the existing60-second default/ten-minute maximum deadline; the subscription exposes its current jobId and revision and releases all but at most two pinned finished revisions/epochs under the same26-job/global-result limits. Publish atomic monotonically increasing subscription dataset revisions, expire old cursors explicitly, and include jobId with every revision notification. Completed append-only events are incrementally inserted; prior provisional/open multiline contributions are retracted/replaced from their starting byte/event boundary. Generational invalidation cancels/stales every derived plan from that generation. Unbounded future-late updates are not promised: a lateness budget specifies revise-window/mark-too-late/rescan behavior. Unsupported incremental stages, such as an exact quantile whose retained sample cap is exceeded, declare `requires_rescan` and expose the next bounded job; they do not show a falsely current value.

- [ ] `F11_two_panels_share_one_read_and_parser_pass`: counter/reader instrumentation with two compatible queries observes one raw read and one parse per physical block; incompatible profile/scope/time policy observes separate plans. Cancelling consumer A leaves B running; cancel last consumer stops worker and releases owner-thread leases.
- [ ] `F11_slow_consumer_does_not_block_peers`: stall A beyond its eight-batch/4MiB credit while B drains; B completes, A reports its bounded backpressure outcome, and no active/retained global limit is exceeded. Queue/deadline time remains included.
- [ ] `F11_live_replaces_tails_and_publishes_atomic_revisions`: successive appends `value=1`→`value=12\n` produce sum12/count1, never13/count2; a multiline tail does the same. Pages never mix revN/revN+1; old cursors return old pinned revision or stale_cursor consistently; rewrite/rotation marks all dependent jobs historical, preserving unrelated source jobs.
- [ ] Add `subscribe_dataset`, `pause_dataset`, `resume_dataset`, `unsubscribe_dataset`, `get_dataset_subscription` and shared-plan diagnostics. GUI live/pause/follow/rescan status and CLI/MCP report the same frontier/revision/lag/too-late/partial state. Run stressed concurrent capture/search/count/chart/table scenarios and existing scheduler/worker/close suites; measure P00 memory/latency/cancellation rather than claiming bounds as speed, then commit.

**Acceptance:** dashboards with ten compatible panels do not run ten independent whole-file parsers; live retention remains constant with growing input, and every panel reports whether its revision is current. **Rollback:** disable shared-plan reuse or live subscriptions separately; existing frozen snapshot jobs remain functional. **Primary references:** [B1](https://github.com/dm17ryk/klogg/blob/bd74c338424845a2caac03d62fdff5187e7e8f0a/src/logdata/include/sourcelocation.h)–[B4](https://github.com/dm17ryk/klogg/blob/01cb637be7c96f2c9e3925247510c162380736b7/src/logdata/include/valuecountjob.h), [D5](https://github.com/64x-lunicorn/LogSquirl/blob/a88c4a4d1c701ab1dda528a5f284ee7d43d873e1/src/ui/include/chartextraction.h), [R10](https://grafana.com/docs/loki/latest/query/metric_queries/).
