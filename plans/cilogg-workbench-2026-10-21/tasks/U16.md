# U16 — Split the main window into panes

**Read first:** [product specification](../00-product-spec.md), [execution guide](../MASTER_GUIDE.md),
the shared contracts in [04-workspace.md](../04-workspace.md), and the
[split-pane design](../../../docs/split-panes.md). Execute only this task or its recorded,
independently reviewable slice.

**Integrated hard dependencies:** G01. Under decision [D12](../../../docs/workbench/decisions.md)
the user authorized this task ahead of G02/G03 completion, and under decision D13 approved its design
on 2026-11-13, so G02/G03 are not hard edges of U16; it uses the existing test suites and the G03
parity harness as they are. U03 and R04 depend on U16.

**Status:** design approved by the user on 2026-11-13 (decision D13); implementation is next, in
slices U16a, U16b and U16c.

**Outcome:** One CILogg window shows two or more panes, side by side or stacked; each pane has its own
file tabs and, per tab, its own log view and filtered views, like several CILoggs running in parallel.

**User request (2026-11-13):** "can we make main window splittable, like we run 2 and more ciloggs in
parallel. so every splitted part will have log files tabs and filtered part".

**User decisions (2026-11-13):**

1. Closing a pane that has tabs asks for confirmation: "Close all its tabs", "Move them to the
   neighbouring pane", or Cancel. An empty pane closes without asking.
2. "Focused tab" is the current tab of the active pane of the active window, for tools and CLI
   defaults.
3. Up to 8 panes per window; `Ctrl+Alt+Right` / `Ctrl+Alt+Down` split right / down. The number of
   tabs and files per pane is not limited, as today with one pane.

**Coordination:** U16 is the first slice of the pane layout U03 plans, so U03 depends on U16: U03's
workspace snapshot embeds this pane layout instead of defining another one. U08 tab groups live inside
a pane. All of them address tabs by tab id.

**Interfaces (proposed additions):**

- `TabbedCrawlerWidget::detachTab(int index) -> DetachedTab` and
  `attachTab(DetachedTab, int index = -1) -> int`. `DetachedTab` carries the `CrawlerWidget`, the
  complete tab-bar data (tab id/UUID, path, display name, COM, Actions-port and script-active
  metadata, data status) and the tab's `streamSessions_` entry. `detachTab` disconnects the tab's
  signals from the source pane; `attachTab` reconnects them in the target pane and keeps the tab id.
  The existing `addCrawler` / `removeCrawler` stay for opening and closing tabs; they are never used
  to move one.
- `LogPane` owns one `TabbedCrawlerWidget` and a stable pane UUID; `MainWindow` gains
  `activePane()`, `panes()` (layout order) and `paneForTabId(id)`.

**Slices:** U16a pane tree, split / close (with the confirmation above) / merge / move through menus,
the tab transfer API, active pane, session and project restore with migration; U16b Commander / CLI /
MCP / Python pane operations; U16c drag and drop between panes.

**Acceptance:** Two panes show different files with independent searches and filtered views; tabs move
between panes keeping their tab id, connection, actions and scripts without restarting anything;
closing a pane with tabs asks whether to close or move them; at most 8 panes per window; the layout
survives a restart and old sessions and projects open in one pane; every existing Commander tab
selector keeps its meaning.

**Rollback:** Merge all panes into one; saved layouts are ignored and all tabs open in one pane.
