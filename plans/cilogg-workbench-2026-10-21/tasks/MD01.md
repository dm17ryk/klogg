# MD01 — Prove real TShark and Lua application-PDU decoding

**Read first:** [decoder contract and acceptance matrix](../10-message-decoders.md), [product specification](../00-product-spec.md), [execution guide](../MASTER_GUIDE.md), and the owning F/E/U/D contracts.

**Integrated hard dependencies:** G01, G02, G03. Existing owner tasks retain their original edges; additional live/Protocol Lab/release capabilities are gated where stated below.

**Existing owners:** E01, E09. **State:** planned; proposed names/files below are not implemented APIs.

**Files:** Create tests/plugins/test_message_decoder_pdu.py and sanitized test_data/message_decoders fixtures; use the installed TShark/text2pcap processes and actual Lua packs. No product capability is advertised by this proof.

**Interfaces:** Consumes exact application bytes, named dissector and engine/script versions; produces a normalized proof report with field tree, diagnostics, byte origins, capability failures and fixture hashes.

**Implementation steps:**
- [ ] Audit installed TShark/Lua/dissector capabilities, obtain the actual EHCP/EHCI scripts and complete reference fixtures, record licenses/hashes and distinguish missing inputs from failed decoding.
- [ ] Write failing fixtures for named Exported-PDU dispatch, complete EHCP/EHCI and partial EHCI; compare normalized output with the same engine/scripts on genuine reference captures.
- [ ] Run real native/Lua dissectors through TShark; prove repeated/generated/transformed fields and incomplete input behavior without a Proto/Tvb/TreeItem interpreter or second semantic parser.
- [ ] Demonstrate a nested SRING-to-EHCP call, including the supplied local 48-byte/counter-9/D50D oracle. Commit only sanitized equivalents with recomputed checksums.
- [ ] Record exact tool versions, argv, fixture hashes, results and unsupported mappings; do not label source inspection or checksum calculations as runtime compatibility.
- [ ] Before symbol edits run impact analysis and refresh relevant indexes. Register tests in existing CMake targets, tag integration tests `[ui]` or `[logdata]` as appropriate, observe failing then passing cases, run required complete checks and record evidence/limitations in PROGRESS.json. Use current build scripts from build_root.

**Acceptance:** Actual-engine dispatch and complete/partial field-tree fidelity pass; absent scripts/captures remain an explicit input blocker. Framing/product integration cannot be declared proven from the addendum alone.

**Rollback:** Disable/revert consumers and public operations before shared backend/contracts; preserve original capture data, existing JSON previews, settings and plugin-v1 compatibility.
