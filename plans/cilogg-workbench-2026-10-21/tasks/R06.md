# R06 — Make problem reports debuggable

**Read first:** [product specification](../00-product-spec.md), [execution guide](../MASTER_GUIDE.md),
and the shared contracts in [09-release.md](../09-release.md). Execute only this task or its recorded,
independently reviewable slice.

**Integrated hard dependencies:** G01. Under decision
[D15](../../../docs/workbench/decisions.md) the user authorized this work ahead of G02/G03 completion
on 2026-11-15, so G02/G03 are not hard edges of R06; it uses the existing Windows build script and
unit suites as they are. R04 depends on R06.

**Outcome:** A problem can be debugged after the fact, also when it happened during unattended
automation: CILogg writes a local report bundle with what happened, the file involved, the memory
of CILogg and of the computer, the steps that led there and a replayable list of the Commander
requests, plus a crash dump for real crashes. The public GitHub issue gets only a summary.

**Reported symptom (2026-11-15, release continuous-26.04.2.1203, Windows):** during automatic
actions a dialog offered to create an issue for `CheckFileChangesOperation failed: bad allocation`.
The prefilled issue held only that line and the versions: no file, no memory numbers, no activity.
At the time the computer had 1.9 GB of 85.9 GB commit free (old Claude sessions and their MCP
servers held most of it) while CILogg held 0.83 GB, so the 5 MB read buffer of the change check
failed because the computer was out of memory. Nothing in the report could show that: file logging
is off by default and every release build has crash dumps disabled (`KLOGG_USE_SENTRY=OFF`, and
the Windows crashpad backend fails to start without a DSN).

**Files and ownership:** `src/crash_handler/` (`diagnostics.*` new, `issuereporter.*`),
`src/logging/` (always-on tail of warnings and errors), `src/logdata/src/logdataworker.cpp` and
`logfiltereddataworker.cpp` (the operation, file and sizes of a failure), `src/ui/src/actionruntime.cpp`
and `streamsession.cpp` (journal hooks), `src/app/kloggapp.h` (reports folder, context, command
journal, `list_reports` / `create_report`), `src/app/cli.h`, `src/ui/*/commander.*`,
`src/ui/src/mainwindow.cpp` (Help > Report a problem), `tests/unit/diagnostics_test.cpp`,
`docs/diagnostics.md`.

**Slices:**

- **R06a (this PR):** activity journal; memory status and 10 s sampling; the report bundle
  (`report.md`, `report.json`, `journal.log`, `repro.json`, `cilogg.log`, `memory.csv`,
  `context.json`, zip; 20 kept); background errors carry operation, file and sizes; one report per
  problem per 10 minutes with a repeat count; a non-modal notice (none in automation); Help > Report
  a problem; `list_reports` and `create_report` through Commander, CLI, MCP and Python; the public
  issue text without paths, journal or log lines.
- **R06b (issue #155):** crash minidumps in release builds (Windows: a local-only crashpad database or
  `MiniDumpWriteDump` from an unhandled-exception filter; Linux/macOS: crashpad or core dumps),
  the stack where a caught exception was thrown, a small all-threads minidump written with an
  exception report, and the Windows `.pdb` files published with each release so dumps can be
  symbolized. Full-memory dumps only as an opt-in setting. A dump is a memory image and can hold
  secrets that were in use, such as a plugin repository token (E15, decision D16): dumps stay out
  of the shareable report zip unless the user adds them, and the notice says they must be shared
  only privately.

**Interfaces (R06a):**

- `cilogg::diagnostics::ActivityJournal::record(category, text, data)`: bounded (2,000), thread-safe;
  an entry equal to one of the last four is folded into it with a repeat count.
- `MemoryStatus currentMemoryStatus()`, `MemoryMonitor::start()`: process private / working set /
  peak, system RAM and commit; journals low system memory and process growth above 1 GB.
- `DiagnosticReports::setRoot/setContextProvider/create/list/find/issueTitle/issueBody`.
- `IssueReporter::reportException(ReportRequest)`, `IssueReporter::reportProblem()`.
- `logging::recentLogLines()`: warnings and errors always; lower levels while logging records them.
- Commander `list_reports`, `create_report [--text <note>]`.

**Interfaces (R06b):**

- `cilogg::diagnostics::CrashDumps::install(folder)`: handlers for unhandled exceptions, fatal
  signals, `std::terminate` and `abort()`. They write `crash-<time>-<pid>.txt` into
  `reports/crashes`, plus a minidump on Windows (small by default, full memory with
  `logging.fullMemoryCrashDumps`). `setFolder`, `pendingCrashes`, `markReported`, `prune(10)`,
  `writeProcessDump` (written by a helper process: `setDumpHelper`, and `runDumpHelper` first
  in `main()`), `writeCrashForTest`.
- `installThrowSiteCapture()` / `currentThrowStack()`: the stack where the calling thread last
  threw (Windows: a vectored exception handler; Linux/macOS: CILogg's `__cxa_throw`).
- `ReportRequest::throwStack`, `processDump`, `attachments`, `privateFiles`;
  `ReportResult::processDump`; `DiagnosticReports::reportPendingCrashes()`,
  `dumpPrivacyNote()`; `IssueReporter::reportPendingCrashes()` at startup. Dumps never go into a
  report zip.
- MSVC Release builds use `/Z7` and link with `/DEBUG /OPT:REF /OPT:ICF`, so the release
  `-pdb.zip` holds the `.pdb` files; `prepare_release.cmd` fails without `cilogg.pdb`.

- [x] R06b in its own PR (issue #155): cases tagged `[diagnostics]` in
  `tests/unit/crashdumps_test.cpp` (throw site, process minidump, crash record to crash report
  with the dump outside the zip, exception report with throw site and minidump, pruning, and a
  real crash of `crash_fixture` for segv, uncaught throw and abort).

**Acceptance:** After a background error, the report folder alone tells which operation failed on
which file, how much memory CILogg and the computer had, what CILogg did in the minutes before
(commands, actions, responses, COM and file events) and which requests to replay; the GitHub issue
text holds no folder, journal or log content; a repeating error writes one report per 10 minutes
and never blocks CILogg. With R06b, a crash leaves a symbolizable dump.

**Rollback:** Revert the PR. Report folders left behind are plain files; the previous code ignores
them.
