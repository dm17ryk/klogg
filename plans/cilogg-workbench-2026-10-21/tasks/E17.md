# E17 — Advanced plugin SDK: menus, rich elements, tooltips with handlers and window integration

**Read first:** [advanced plugin SDK design](../../../docs/plugin-sdk-advanced.md),
[plugin views](../../../docs/plugin-views.md), [plugin SDK](../../../docs/plugin-sdk.md), the shared
contracts in [08-ecosystem.md](../08-ecosystem.md) and [decision D17](../../../docs/workbench/decisions.md).

**Integrated hard dependencies:** E14 (completed), the view SDK this task extends. Design proposed on
2026-11-19 under decision D17 and accepted the same day with every recommended answer, including a
separate yes to question 13 (E17i last); E17 is in progress and in `PROGRESS.json.runnableTasks`,
authorized ahead of G02/G03 like E13a and E15, starting with slice E17a.
R04 depends on E17. E01 later absorbs the versioned host features and the plugin's `features`
(coordination, no hard edge).

**Outcome:** a process plugin can add its own menu and submenus under Plugins (and optionally one
top-level menu), and entries to the tab, pane, log view and filtered view context menus, with
conditions, check marks, radio groups, dynamic submenus and user-editable keyboard shortcuts. Choice
fields and table cell editors offer plain drop-downs, drop-downs with icons, with check boxes and with
radio marks, plus inline styles and `checkbox`, `radio_group` and `check_group` elements. Tables hold
icons, cell tooltips, tones and progress, keep Shift and Ctrl multiple selection and gain a toggle
mode, plugin-set selection, row events, context menus, Copy and Export. Every element, cell, tree
node and status item can have a static tooltip and an advanced tooltip filled by a plugin handler
through a host query with a timeout and a cache. A `tree` element and a `file_tree` folder and file
browser support Shift and Ctrl multiple selection. Beyond the request: versioned host features and
plugin `features`, host queries, an icon model, layout containers, a Markdown text pane, images and
charts, validation and more field kinds, dialog results, toolbars, status items, notifications,
clipboard, drag and drop, view state and session restore, theme events, settings pages in Options,
richer message boxes and file dialogs, accessibility names, typed SDKs with a fake-host test harness,
JSON Schemas and a protocol log; optionally (separate approval) a bounded command channel from plugins
to the host. The protocol version stays 1; a plugin that does not opt in gets the same messages with
the same keys as today (only `initialize` gains additive keys), and older hosts still load manifests
that use the new keys.

**Files and ownership:** `src/plugins/` (`pluginprocess.cpp` initialize keys, a new `pluginqueries.*`,
`pluginmanager.cpp` message routing and UI notifications, `pluginmanifest.cpp` validation of `menus`,
`toolbars`, `status_items`, `settings_view`, `requires` and `shortcut`), `src/ui/` (`pluginview.*` with
the table model moved to `plugintablemodel.*`, new `plugintooltips.cpp`, `pluginchoicewidgets.cpp`,
`plugintree.cpp`, `pluginfiletree.cpp`, `pluginlayout.cpp`, `plugintextview.cpp`, `pluginchart.cpp`,
`pluginmenus.*`; hooks in `pluginuicontroller.cpp`, `pluginviewhost.cpp`, `mainwindowpanes.cpp`,
`abstractlogview.cpp` through a new `PluginMenuHost` interface, `optionsdialog.cpp`), the shortcut
registry (`src/settings/include/shortcuts.h`), Commander tables, CLI help and native MCP,
`plugins/sdk/python/` (SDK, `cilogg_plugin_testing.py`), `plugins/sdk/cpp/` (SDK, testing header, view
example), `plugins/examples/ui-gallery/`, `Resources/schemas/plugins/`, `docs/plugin-views.md`,
`docs/plugin-sdk.md`, `docs/plugin-sdk-advanced.md`, tests in `tests/ui/workbench_e17_test.cpp`,
`tests/unit/plugins_test.cpp`, `tests/plugins/` and `tests/mcp/workbench_parity.py`.

**Slices:**

- **E17a:** capability negotiation (`host_feature_versions`, `host_version`, `host_limits`, the
  manifest's `handles` and `requires`, the plugin's `sdk` and `features`); host queries (`q:` ids
  checked per plugin, sent only while ready and reading, timeouts, `query/cancel`, concurrency
  limits, circuit breaker, statistics in `get_plugins`); icons (plugin files, `builtin:`, `status:`,
  registered icons and pictures, light and dark variants, `icon_ref` on actions and views); element
  tooltips made plain text, static tooltips on existing elements and column headers, advanced
  tooltips through `tooltip/resolve` on every existing element and per table cell, with the cache and
  `tooltip/invalidate`; `get_plugin_tooltip`; accessible names from captions; the table model moved
  out of `pluginview.cpp`; SDK forward compatibility (unknown requests answered `-32601`, unknown
  notifications ignored) and backward compatibility (builders fall back on older hosts), type hints,
  the fake host, golden-frame and version-skew tests.
- **E17b:** `menus` in the locations `plugins`, `menubar`, `tab`, `pane` and `log` (`element`
  needs the element context menus of E17d and comes with it);
  separators, sections, submenus, checkable and radio entries, `when` conditions, `menu/update`,
  dynamic submenus through `menu/populate`, `action`, `view` and `event` entries with `ui/command`;
  placement, "More" and per-plugin hiding; `shortcut` keys in the shortcut registry with rebinding in
  Options and conflict reporting; `get_plugin_menus` and `trigger_plugin_menu`.
- **E17c:** choice objects with icons, separators and sections; `indicator: "radio"`, inline `radio`
  and `checkboxes` styles, `searchable`, `editable` and `completion` (`field/complete`); `checkbox`,
  `radio_group` and `check_group` elements; the same choices in cell editors; field kinds `multiline`,
  `secret`, `integer`, `slider`, `color`, `date`, `time`, `datetime`; validation and
  `requires_valid`.
- **E17d:** cell objects (icon, tooltip, tone, bold, progress, sort value), row icons and check boxes,
  column options, `header: false`, `toggle_selection`, the `select` patch and `current`, `activated`,
  `checked` and `moved` (reordering inside the table) events, `context_menu` on elements, Copy, Copy
  All and Export CSV, the per-view state store with kept columns.
- **E17e:** the `tree` element (lazy children through `tree/children`, patches, selection, check boxes,
  rename, reorder inside the tree) and the `file_tree` element (roots, filters, files and folders,
  Shift and Ctrl multiple selection); dragging out to other targets comes with E17g.
- **E17f:** `tabs`, `tab`, `splitter`, `form`, `grid`, `separator`, `spacer` and size hints;
  `text_view` (plain or Markdown with HTML off, append, follow); `image`, `sparkline`, `chart`; button
  icons, styles, drop-down menus, check state and default; busy overlay; `modified` with a close
  confirmation; dialog buttons with a result; focus patches.
- **E17g:** plugin toolbars, status-bar items, notifications, clipboard write, drag and drop between
  elements, files and panes, the rest of view state and session restore, theme in `initialize` and
  `ui/theme_changed`, settings pages in Options, message box details, check box and input, file
  dialogs on demand, opt-in host events (`ui/focus_changed`, `tab/opened`, `tab/closed`,
  `log/selection`).
- **E17h:** JSON Schemas, `python -m cilogg_plugin validate`, the protocol log, developer mode, the C++
  view example.
- **E17i:** the host-command channel (`host/command`, allowlist, origin `plugin`), only after the user
  approves question 13 of the design.

**Interfaces (proposed additions):** see sections 4 to 16 of the design. Initialize params
`host_feature_versions`, `host_version`, `host_limits`, `theme`; initialize result `sdk`, `features`;
manifest keys `handles`, `menus`, `toolbars`, `status_items`, `settings_view`, `requires`, `shortcut`
(on actions, views and entries), `icon_ref` (actions and views), `restore` (views); host queries
`tooltip/resolve`, `menu/populate`, `tree/children`, `field/complete`; notifications `query/cancel`,
`ui/command`, `menu/update`, `toolbar/update`, `status/update`, `tooltip/invalidate`, `ui/icons`,
`ui/notify` and `ui/notification_result`, `ui/clipboard`, `ui/file_dialog` and
`ui/file_dialog_result`, `view/state`, `ui/theme_changed`, `ui/focus_changed`, `tab/opened`,
`tab/closed`, `log/selection`; Commander operations `get_plugin_menus`, `trigger_plugin_menu`,
`get_plugin_tooltip`. No existing message changes meaning and no existing enumeration gains values.

**Implementation steps:**

- [ ] For each slice, write failing Catch2 cases tagged `[workbench][E17]` and `[plugins]`, Python SDK
  tests under `tests/plugins/` and the E17 parity case, and confirm that they fail before the change.
- [ ] Implement E17a, pass its cases and the unchanged E13, E14 and E15 suites and the ADB, syslog and
  view-demo fixtures, review the diff and deliver it as a focused PR.
- [ ] Implement E17b to E17h in order, each as its own branch and PR with the host, both SDKs,
  `ui-gallery`, docs and tests, merging master before each slice.
- [ ] Implement E17i as the last slice (question 13 approved on 2026-11-19).
- [ ] Build each slice with MSVC `/W4 /WX` and check the GCC and Clang warning set
  (`-Wshadow -Wconversion -Wsign-conversion -Werror`); verify through GUI, CLI, native MCP and Python;
  run the complete unit and integration suites; record evidence and limitations in PROGRESS.json.

**Acceptance:** a plugin adds a submenu under Plugins and entries to the tab, pane and log context
menus that run actions, open views and send events with the right context; its shortcuts can be
rebound in Options; a view shows each of the four drop-down styles, check box and radio elements, a
table with icons, per-cell tooltips and an advanced tooltip answered by the plugin within its timeout
(and cached), Shift and Ctrl multiple selection in a table, a tree and a file tree; the same results
come through the GUI, the CLI, native MCP and Python; a plugin that uses none of this, and an older
SDK copy, behave exactly as before; an older CILogg still loads a manifest that uses the new keys.

**Rollback:** revert the slice PRs. Plugins that use the new keys then run without them: older hosts
ignore unknown manifest keys, element types and properties, and send no new messages; saved plugin
shortcuts and view state stay unread in the settings.
