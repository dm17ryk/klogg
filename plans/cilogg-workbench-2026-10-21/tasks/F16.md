# F16 — Recursive folder manifests/search, lazy bounded readers, grouped results, and validated reopen

**Read first:** [product specification](../00-product-spec.md), [execution guide](../MASTER_GUIDE.md), and the shared contracts in [02-data.md](../02-data.md). Execute only this task or its recorded independently reviewable slice.


**Integrated hard dependencies:** G01, G02, G03, F01, F07, F08. Capability-conditional dependencies described below are additional runtime gates; they do not reverse these edges.


**Purpose:** Implement the actual P07/P08 directory investigation capability, including files that were never opened in a viewer, without holding thousands of LogData objects or treating a pathname as source identity. **Depends on:** F01/F07/F08. F13 optionally enables compressed members through the same reader capability; ordinary files work without F13. F02/F03 profile selection/parsing is available through F07; assembly/time/aggregate features activate only when their own tasks are present. F07 has no dependency on F16 and can ship first with folder capability unavailable. **Current anchors:** existing `AnalysisJobService` admission/backpressure/expiry, `AnalysisRequest` physical scope rules, `encodingdetector.*`, `src/logdata/src/{logdata,fileholder,filedigest}.cpp`, raw matcher/capture worker, `src/ui/src/{crawlerwidget,mainwindow}.cpp`, Commander/native MCP. The checked master has no folder search engine/model; this card owns those additions rather than referring to a future unowned roadmap step.

**Proposed files:** create `src/logdata/include/boundedstreamreader.h` and `src/logdata/src/boundedstreamreader.cpp`; `src/analysis/include/{foldermanifest,foldersearchengine,foldersourcereader,deferredfileresolver}.h` and matching implementations; `src/ui/include/{foldersearchdock,foldersearchresultsmodel}.h`, matching implementations, and `src/ui/src/mainwindowfoldersearch.cpp`; `schemas/cilogg-folder-search-v1.schema.json`; `tests/unit/{foldermanifest,boundedstreamreader,deferredfileresolver}_test.cpp`, `tests/ui/foldersearch_test.cpp`, and fixture generator `test_data/analysis/folder/generate_fixture.py`. Modify the actual logdata/analysis/UI/app CMake and test lists, command catalog/dispatch, F07 provider registration and F07 origin resolver registry; integrate F10 inspector when available without making it a prerequisite. F16 owns the ordinary shared stream reader; F13 extends its compressed-input adapter when that capability is present.

**Interfaces:** `QString FolderSearchEngine::createManifest(const FolderScanSpec&,QString* error=nullptr); QString FolderSearchEngine::search(const FolderSearchRequest&,QString* error=nullptr); DataResult<FolderManifestDescriptor> manifest(const QString& manifestId) const; DataResult<SourceSetHandle> sealSources(const QString& manifestId,quint64 manifestRevision) const; DataResult<std::unique_ptr<IAnalysisSourceReader>> openFolderReader(const SourceManifestEntry&,const ReaderBudget&); DataResult<VerifiedFileBinding> verifyDeferredFile(const DeferredFileOrigin&,const SourceManifestEntry&,const ResolvePolicy&,const std::atomic_bool&); QString materializeDeferredFile(const EventRef&,const ResolvePolicy&,QString* error=nullptr);`. `FolderSearchRequest{FolderScanSpec scan;QuerySpec query;ContextSpec context;quint64 requestRevision;AnalysisLimits limits;}`; raw literal/regex line matching is an explicit query source/matcher mode using existing semantics, while typed field predicates use F08. `ContextSpec{quint32 before,after;bool mergeOverlaps;}` defaults0/0, with maximum100 lines each and bounded context bytes. Match rows and context rows have distinct roles; counts exclude context.

`FolderScanSpec` fixes an absolute root; recursive/includeHidden/followLinks flags; include/exclude globs against normalized root-relative `/` paths; glob case policy; forced/auto encoding; per-source profile binding/detection policy; `includeCompressed=false`; verification mode; and resource ceilings. Defaults: recursive=true, hidden=false, followLinks=false, include=`**/*`, maxDepth64, maxFiles10,000, manifestBytes16MiB, maxOpenReaders4 globally for folder work, maxFileConcurrency2 within existing scheduler admission, maxScanBytes2GiB and maxFileBytes2GiB. These are explicit configurable initial limits, not large-file performance claims. Directory enumeration is streamed and cancellation-aware; manifest entries are stored under the entry/byte caps. Excluded directories are pruned before descent; no traversal of symlink/reparse directories by default; explicit link traversal detects cycles by platform identity/canonical target and rejects outside-root traversal unless separately selected. Unreadable/deleted/too-large/unsupported-compressed/cycle/depth-limited files have visible reasons and summary counts. Hardlink/canonical-target dedup is an explicit policy (default retain distinct relative paths), not hidden text deduplication. Final groups sort by normalized relative path, then physical event/occurrence order; capped traversal remains visibly partial and does not claim globally exhaustive lexical membership.

The reader streams ordinary files without constructing a persistent full line index. It preserves BOM/forced encoding precedence, decoder state across chunks, exact original byte offsets, raw LF/CRLF/final-line rules and physical UTF-16 spans. It uses the same 256-line/1MiB block and 1MiB physical-record limits and the same matcher/capture-worker budgets as open sources. Oversized/malformed/short-read inputs produce a named per-file outcome; no padded bytes or guessed offsets are exposed. A query freezes each file's read watermark/content epoch when it is admitted; discovery is not an atomic filesystem-wide snapshot. Directory discovery and file scans overlap within one ordinary admitted pipeline so early file results arrive before all files are scanned; its growing manifest is explicitly `building`, then sealed or marked partial. Only sealed immutable manifest revisions may be reused by a later `freezeSources(folderManifestHandle)`. Previously published pages identify their exact manifest revision; no page silently changes file identity. All work uses the current analysis scheduler and bounded credits, not a second worker pool or unbounded file-result queue.

**Deferred identity/materialization:** never create a SourceSnapshot/SourceLocation for a directory entry that has no real open LogData. A `DeferredFileOrigin` points to the manifest entry and its observed line/byte ranges. During scanning, capture platform identity/size/change metadata, the exact consumed-prefix SHA-256 and final/provisional boundaries; retain hits only within accounted query-state/pending limits until their verification descriptor is finalized. Optionally retain immutable raw backing under an explicit default256MiB/job and512MiB global backing quota; no policy pins every file or all readers. Once a file is processed its OS reader can close; all10,000 manifest entries remain metadata only. File replacement/deletion/closure between results and navigation is therefore expected, not a reason to retain10,000 open LogData instances.

F07's `resolve` checks an existing verified binding quickly; otherwise its `materialize_dataset_event` route calls F16's normal cancellable job. F10's lineage inspector later consumes the same operation. It validates the manifest/content epoch and strong frozen-prefix digest (or immutable backing), rechecks origin identity and exact line-to-byte mapping/encoding/assembly, then opens/indexes through the current owner-thread UI/source path and calls the *fresh* SourceSnapshot's `location`. The returned `VerifiedFileBinding` includes original deferred ref, new physical ref with the actual new open UUID, verification mode/digest/watermark and binding revision. Same path/file ID/size/mtime or a sampled hash alone does not authorize rebinding. If a file grew, closed completed ranges may rebind only when their full frozen prefix is strongly validated; an event touching the old provisional final line is rejected as `provisional_replaced`. If bytes changed, return `stale_source` and offer an explicit new search against current content. A retained old backing can open historical context clearly labeled with the original manifest; it cannot claim to be the current source. Verification over its configured bytes/deadline returns `verification_limit`/timeout. The old deferred reference is retained unchanged and is never relabeled as a new SourceLocation.

## Review focus and required cross-feature scenarios

1. **A value at numeric/transport limits:** UInt64 max, integers above2^53, long exact decimals, invalid/nonfinite values, typed unit mismatch. Owned by F01/F03/F08/F09/F15 tests.
2. **A growing event whose interpretation changes:** UTF-16 provisional final line, multiline continuation, new time/lookup/profile revision, late event/window retraction. Owned by F01/F04/F05/F09/F11 tests.
3. **A source that is no longer the source:** same-size rewrite with preserved mtime, rotation/replacement/truncation/closure, deferred folder reopen/new real UUID, managed byte generation/segment expiry, and decompressed backing lifetime. Owned by F01/F06/F07/F10/F13/F15/F16 and D01 tests.
4. **A dashboard that overwhelms the reader:** ten panels, stalled consumer, high-cardinality group/pivot, exact quantile state, cancellation during worker/decompression/lookup. Owned by F07/F09/F11/F13/F14 tests.
5. **A gap mistaken for a zero or a timestamp:** unknown timezone/DST, unreadable/missing-time interval, capture gaps, uptime reset, observed versus read/event time. Owned by F05/F06/F09/F15 tests.

Run the combined fixtures with an active COM/ADB/syslog capture while raw searching, counting, charting, structured table filtering and export occur. Check generation/provisional boundaries, open/close/reopen, escaped raw copy and Value Names, parser failure visibility, UI event latency, memory/state/disk peaks and transport parity together. Record all numerical P00 release budgets before claiming scale/performance completion; allocation limits alone do not prove throughput, bounded latency, or successful cancellation of a stalled OS read.

- **[R12](https://github.com/lz4/lz4/blob/dev/doc/lz4_Frame_format.md)** LZ4 upstream [frame format](https://github.com/lz4/lz4/blob/dev/doc/lz4_Frame_format.md) and [lz4frame.h](https://github.com/lz4/lz4/blob/dev/lib/lz4frame.h): frame detection/streaming contracts; pin the chosen revision before packaging.
