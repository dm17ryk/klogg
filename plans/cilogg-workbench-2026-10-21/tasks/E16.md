# E16 — Preview packs: versioned previews, Lua and Python decoders as plugins

**Read first:** [plugin repositories and preview packs design](../../../docs/plugin-repositories.md)
section 4, [TShark/Lua message previews](../../../docs/workbench/tshark-preview.md),
[tasks/E15.md](E15.md) and [decision D16](../../../docs/workbench/decisions.md).

**Integrated hard dependencies:** E15 (packs install and update from plugin repositories). Decision
D16 records the design as proposed on 2026-11-17; implementation starts only after the user approves
it. E09 depends on E16, so the later general packs extend this pack format instead of duplicating
it; R04 depends on E16. MD03 activates the packs' Python decoders; that is a coordination note, not a
hard edge.

**Outcome:** a preview pack is a plugin package (`"kind": "preview-pack"`) that carries preview
definitions in the format of `previews.json`, Lua decoders for TShark and Python decoders. Packs are
versioned, installed, updated, enabled and removed like plugins, from the same repositories or from a
local zip. Their previews are read-only (Copy to My Previews makes an editable copy), and their Lua
is loaded by TShark as trusted scripts while the pack is enabled, because installing it from a
repository the user added is the trust decision. Protocol Lua that must stay private is delivered
from a private repository instead of being published.

**Files and ownership:** `src/plugins/src/pluginmanifest.cpp` and `pluginmanager.cpp` (the pack
kind, validation, no process), `src/ui/src/previewrepository.cpp` and a new `previewpackregistry.*`
(merged read-only previews, precedence of user copies), the preview settings UI (lock, pack name,
Copy to My Previews), the TShark profile snapshot (pack Lua and routes merged at session start, never
into the saved configuration; the profile limit raised from 8 to 32 in `tsharkpreviewclient.cpp`,
`scripts/plugins/message_decoder_preview_worker.py` and `scripts/plugins/message_decoder_pdu.py`;
the route limits; discarded sessions on change), the Plugins window
(kind, "Needs TShark"), `docs/plugin-sdk.md`, `docs/workbench/tshark-preview.md`, an example pack
under `plugins/examples/`, tests in `tests/unit/plugins_test.cpp`, `tests/unit/previewdecoder_test.cpp`
and a new `tests/ui/workbench_e16_test.cpp`.

**Slices:**

- **E16a:** the pack kind with JSON previews and Lua for TShark, read-only previews with Copy to My
  Previews, `decoder_routes`, the public example pack, and pack fields in `get_plugins`.
- **E16b:** Python decoders run through the MD03 decoder contract. Until MD03 exists, E16a installs
  and updates them with the pack and lists them as requiring a newer CILogg.

**Interfaces (proposed additions):** manifest keys `kind`, `pack_format`, `previews`, `lua`
(`folder`, `load`), `decoder_routes`, `python_decoders`; `PreviewPackRegistry::previews()` and
`luaProfile()`; the `get_plugins` field `kind` and, for packs, `previews`, `luaFiles` and
`pythonDecoders` counts.

**Implementation steps:**

- [ ] Write failing cases tagged `[plugins]`, `[previewdecoder]` and `[workbench][E16]`: pack
  manifest validation (`kind` read first, no process keys, `protocol_version: 1`, every Lua file
  listed, at most 8 files of 1 MiB inside the folder, preview routes naming only pack previews),
  process operations rejected for packs, read-only previews and the copy, user precedence, pack Lua
  in the profile snapshot only while enabled (copied, hashed in `scriptSha256`, loaded in the listed
  order, never written into the saved configuration), the 32-file and route limits, sessions
  discarded on enable, disable and update, JSON fallback without TShark, and inactive
  `python_decoders`.
- [ ] Implement E16a in the owned files, add the public example pack (synthetic protocol, no private
  Lua), and pass the new cases plus the existing preview, TShark and plugin suites.
- [ ] Verify install, update, enable and disable of a pack through GUI, CLI, native MCP and Python,
  build with the existing Windows build script, run the complete suites, record evidence and
  limitations in PROGRESS.json and deliver a focused PR.
- [ ] E16b in its own PR once MD03's decoder contract is merged.

**Acceptance:** installing a pack from a repository adds its previews (read-only) and lets TShark
decode with its Lua without per-file approval; updating it changes the previews and the next decode
uses the new Lua; disabling it removes both; the user's own previews and copies are never changed by
a pack; previews still fall back to JSON when TShark is not configured.

**Rollback:** revert the PR. Installed packs are then listed as invalid plugins and nothing loads
them; `previews.json` and the decoder settings are unchanged.
