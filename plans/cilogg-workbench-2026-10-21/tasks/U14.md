# U14 — Show which filter matched each filtered line, and clear the results

**Read first:** [product specification](../00-product-spec.md), [execution guide](../MASTER_GUIDE.md),
and the shared contracts in [04-workspace.md](../04-workspace.md). Execute only this task or its
recorded, independently reviewable slice.

**Integrated hard dependencies:** G01. Under decision [D12](../../../docs/workbench/decisions.md)
the user authorized this task ahead of G02/G03 completion on 2026-11-13, so G02/G03 are not hard
edges of U14; it uses the existing test suites and the G03 parity harness as they are. R04 depends
on U14.

**Outcome:** The filtered view says why each line is there, and the user can clear the filtered view
without losing the search.

**User request (2026-11-13):** "add column where shown on which value it was chosen" and "ability to
clear filtered logs window". Selecting several predefined filters combines them into one search
(`a|b` for regular expressions, `"a" or "b"` for boolean search), so the filtered view mixes lines
from several filters and does not say which filter selected a line.

**Interpretation confirmed by the user (2026-11-13, decision
[D13](../../../docs/workbench/decisions.md)):** the column names the predefined filter(s) that
matched; a single pattern shows the matched text. "Clear results" empties the view while the search
keeps running, new matches appear, and searching again restores all results.

**Files and ownership:**

- Modify existing `src/ui/src/abstractlogview.cpp` (an optional annotation column beside the line

- Create `src/ui/include/matchlabeler.h` and `src/ui/src/matchlabeler.cpp` (pure labelling logic).
- Modify `src/logdata/src/logfiltereddata.cpp` and its header (clear cutoff and search generation)

- Tests, tagged `[workbench][U14]`: `tests/unit/matchlabeler_test.cpp`, and cases in
  `tests/ui/logfiltereddata_test.cpp` and `tests/ui/crawlerwidget_test.cpp`.

**Interfaces (proposed additions):**

- `MatchLabeler::fromSearch(const RegularExpressionPattern& search, selectedPredefinedFilters)` and
  `label(lineText)`. The labeler receives the typed search the filtered view runs (the
  `RegularExpressionPattern` with its mode — regular expression, plain text or boolean — match mode,
  case sensitivity and inverse flag), never the raw pattern text alone, plus the selected predefined
  filters. It returns the names of the selected predefined filters that match the line when the search
  was built from them; otherwise the top-level alternatives (`|` for regular expressions, `or` terms
  for boolean search) that match; with a single term, the matched text. Marked lines without a match
  show "mark"; context lines show nothing; inverse searches show nothing.
- Filtered view "Matched by" column, toggled from the filtered view's context menu and persisted.
  Labels are computed off the GUI thread, only for visible lines, and cached per search generation;
  the view shows an empty cell until a label arrives.
- "Clear results" (button beside the visibility selector, filtered view context menu) removes the
  search matches found so far and keeps the pattern, options and marks. It records a cutoff (the
  current end of the source) and starts a new search generation: results still in flight from the
  previous generation are discarded, and only matches on lines after the cutoff are added. With
  auto-refresh, new matching lines keep arriving. Running the search again starts a new generation
  without a cutoff and restores all results.
- Marks are user data. "Clear results" never removes marks, so marked lines stay visible in the
  filtered view (with the default visibility "Marks and matches" the view shows their union); with
  the visibility selector on "Matches" the view is empty after a clear.
- Public automation: both controls have stable object names and work through the existing
  `get_ui` / `set_ui` / `activate_ui` Commander, CLI and native MCP operations.

**Acceptance:** With two predefined filters selected, every matching line names the filter(s) that
selected it; the same pattern text in regular expression and boolean mode is labelled by that mode's
alternatives; "Clear results" removes every search match, results scanned before the clear never
reappear, and only lines added afterwards appear; a marked row stays visible after the clear and the
"Matches" view is empty; searching again restores all results; nothing changes in the main view,
marks or search history.

**Rollback:** Hide the column and the clear control; search behaviour is unchanged.
