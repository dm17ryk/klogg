# MD04 — Import typed field trees with exact transformation provenance

**Read first:** [decoder contract and acceptance matrix](../10-message-decoders.md), [product specification](../00-product-spec.md), [execution guide](../MASTER_GUIDE.md), and the owning F/E/U/D contracts.

**Integrated hard dependencies:** G01, G02, G03, MD03. Existing owner tasks retain their original edges; additional live/Protocol Lab/release capabilities are gated where stated below.

**Existing owners:** E01, U04. **State:** planned; proposed names/files below are not implemented APIs.

**Files:** Create plugins/examples/wireshark-decoder/ field-tree import and sidecar modules; create src/logformat/include/decoderfieldmapping.h and src/logformat/src/decoderfieldmapping.cpp. Test tests/ui/decoderfieldmapping_test.cpp and tests/plugins/message_decoder_fields.py.

**Interfaces:** PDML/field metadata plus generated-PDU sidecar -> DecodedField tree with exact values, occurrence IDs, logical buffer ranges, generated flags and zero/many original text/file-byte spans; unknown origins remain explicit.

**Implementation steps:**
- [ ] Write fixtures for repeated field names, arrays, enums/flags, integers above 2^53, generated values and separately transformed/decompressed data sources.
- [ ] Map encapsulation offsets and hex/base64/escape transformations through sidecars; reject the assumption that every PDML pos/size refers directly to original log bytes.
- [ ] Implement bounded tree/field paging, lazy retained buffers and selection mapping without parsing numeric display labels back into values.
- [ ] Verify round trips for UTF-16 source positions, many-to-one fragment assembly, generated fields with evidence but no occupied raw bytes, and explicit unknown mappings.
- [ ] Validate cache identity against source generation/scope, engine version, script hashes, preferences and profile revision; invalidate navigation after rewrites while retaining marked historical output.
- [ ] Before symbol edits run impact analysis and refresh relevant indexes. Register tests in existing CMake targets, tag integration tests `[ui]` or `[logdata]` as appropriate, observe failing then passing cases, run required complete checks and record evidence/limitations in PROGRESS.json. Use current build scripts from build_root.

**Acceptance:** Each mapping reports its origin and fidelity; repeated/generated fields and exact typed chart values survive serialization without fabricated raw ranges.

**Rollback:** Disable/revert consumers and public operations before shared backend/contracts; preserve original capture data, existing JSON previews, settings and plugin-v1 compatibility.
