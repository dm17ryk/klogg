# F04 — Multiline event assembly, stack traces, exceptions, and provisional replacement

**Read first:** [product specification](../00-product-spec.md), [execution guide](../MASTER_GUIDE.md), and the shared contracts in [02-data.md](../02-data.md). Execute only this task or its recorded independently reviewable slice.


**Integrated hard dependencies:** G01, G02, G03, F01, F02, F03. Capability-conditional dependencies described below are additional runtime gates; they do not reverse these edges.


**Purpose:** Group a semantic event across physical lines without corrupting navigation, counts, append behavior or input scopes. **Depends on:** F01–F03. **Current anchors:** `SourceSnapshot` provisional boundary; analysis frozen physical ranges; no multiline assembly in current master. This is an intentional expansion of the original roadmap's deferred scope.

**Proposed files:** create `src/logformat/include/{eventassembler,exceptionsignature}.h` and matching implementations; tests `tests/unit/eventassembler_test.cpp`, `tests/ui/eventassemblysource_test.cpp`; fixtures `test_data/analysis/multiline/`. Add assembly policy to profile schema; consume optional exact raw slices from F01.

**Interfaces:** `AssemblyOutput EventAssembler::consume(const QVector<AnalysisLine>&,const SourceSnapshot&,const AssemblyBudget&); AssemblyOutput finish(EndOfInput); AssemblyOutput replaceFrom(quint64 byteOffset,const QVector<AnalysisLine>&,const SourceSnapshot&); DataResult<ExceptionSummary> summarizeException(const EventRecord&,const ExceptionGroupingPolicy&);`. `AssemblyOutput{QVector<EventDelta> changes;std::optional<AssemblerCheckpoint> checkpoint;QVector<DataError> diagnostics;}`; `EventDelta{Insert|Replace|Retract,eventKey,optional<EventRecord>}`; checkpoints contain bounded open-event segments, start boundary and parser state. Modes: physical-line default; regex start/continue/end with supervised evaluation; indentation/stack trace; delimiter-aware CSV; framed JSON/XML. Limits are 256 lines/1 MiB/event by default, including open provisional state.

On live input, an open event may be published as provisional. Appending retracts/replaces its old contribution under the same event key; it never inserts both old and extended versions. An input byte edit/reload/reset starts a new generation. EOF freeze emits open events with `unterminated` status; an explicit idle flush is provisional and replaceable when continuation arrives. Never group across source IDs/capture streams. Selection/current-matches scope must declare either `physical_only` or `close_events`: the latter expands to the full containing event and returns the added physical ranges, and never stitches discontiguous selected fragments into one fabricated event. The GUI offers raw physical count versus event count explicitly.

- [ ] `F04_append_retracts_open_event_once`: initial `ERROR x\n  at a` produces one two-line provisional event; append `\n  at b\nINFO ok\n` leaves exactly two events, first with three lines and one error occurrence; delta sequence includes Replace/Retract+Insert, never a third counted copy.
- [ ] `F04_scope_and_source_boundaries_are_exact`: continuation at a scan-batch boundary joins its original event; discontiguous selection does not join unrelated rows; close-events reports the exact expanded range; two sources with identical indentation never merge. A quoted CSV newline maps to both physical rows and exact original terminators.
- [ ] `F04_exception_grouping_preserves_evidence`: Java `Caused by`, Python traceback and .NET inner exception retain ordered frame/raw spans. Group signature is based on configured type/message normalization/frames, versioned and accompanied by sample EventRefs; differing signatures stay distinct; normalization never replaces raw messages. Limit overflow emits an event diagnostic and preserves subsequent physical lines for recovery.

GUI expand/collapse and raw context navigation resolve the same first/last line through CLI/MCP; cancel/rewrite/close drops checkpoints without publishing stale deltas. Run assembly/source/analysis regressions and parity, then commit.
