# F05 — Precise timestamps, timezone policies, device uptime, and resets

**Read first:** [product specification](../00-product-spec.md), [execution guide](../MASTER_GUIDE.md), and the shared contracts in [02-data.md](../02-data.md). Execute only this task or its recorded independently reviewable slice.


**Integrated hard dependencies:** G01, G02, G03, F01, F02, F03, F04. Capability-conditional dependencies described below are additional runtime gates; they do not reverse these edges.


**Purpose:** Make event-time semantics reliable before charts/rates/time seeking consume them. **Depends on:** F01–F04; fulfills P10's shared time parser. **Current anchors:** source snapshots carry bytes/lines but no timestamp type; plugin captures may already add timestamps as text. Donor `TimestampReader` is a behavioral reference only: its missing-zone-as-UTC and mtime-derived-year defaults are not adopted.

**Proposed files:** create `src/logformat/include/{timestampparser,clockdomain,timepolicy}.h` and matching implementations; `tests/unit/timestampparser_test.cpp`, `tests/ui/timepolicysource_test.cpp`; fixtures `test_data/analysis/time/`; extend format/time-policy schemas and source profile state.

**Interfaces:** `DataResult<TimeValue> TimestampParser::parse(QStringView,const TimestampSpec&,const ClockContext&) const; DataResult<DurationValue> subtractTimes(const TimeValue&,const TimeValue&,const AlignmentSnapshot*); DataResult<ClockEpoch> classifyUptime(const TimeValue& previous,const TimeValue& current,const ResetPolicy&);`. `TimestampSpec` explicitly fixes ordered format alternatives, `s|ms|us|ns` epoch unit, exact fractional precision, zone policy, date/year anchor policy, leap-second policy and rollover tolerance. `ClockContext` supplies explicit capture metadata, declared timezone/date/boot ID, never the machine's current locale/timezone implicitly.

Preserve written offsets and fractional digits; normalize resolved instants to seconds+nanos without int64-nanosecond overflow. Zone-free civil values remain unresolved until a user/profile policy supplies an IANA zone or explicit offset. For daylight-saving folds/gaps return `ambiguous_local_time`/`nonexistent_local_time` and alternatives; an explicit earlier/later/reject policy records the choice. Date-less time requires an explicit anchor and a rollover policy; a backward jump beyond configured `midnightThreshold=12h` increments date, while smaller backward jumps remain out of order. Uptime/ticks stay in a named device/boot domain; rollover needs declared bit width and modulus; reset begins a new epoch/boot segment. If a decrease could be reorder or reset and metadata is absent, report ambiguity rather than invent continuity. Event time, host observed/capture-receipt time and analysis-read time are distinct fields; mtime can be shown as origin metadata only unless an explicit heuristic policy is selected and labeled.

- [ ] `F05_exact_units_offsets_and_precision`: `1700000000000000001 ns` retains 1 ns; `2026-10-21T10:00:00.123456789+02:00` equals 08:00Z with all nine digits; UInt64 tick values never pass through double; pre-epoch values and dates outside int64-ns range round-trip via seconds+nanos.
- [ ] `F05_unknown_and_dst_are_visible`: zone-free input remains LocalCivil; America/New_York `2026-11-01 01:30` yields two alternatives, `2026-03-08 02:30` reports a gap; configured fold policy produces a provenance flag. Unsupported zone abbreviations stay unresolved. Leap second defaults to an explicit unsupported/invalid status, never wraps silently.
- [ ] `F05_rollover_reset_and_out_of_order_differ`: anchored `23:59:59→00:00:01` advances the date; `10:00:03→10:00:02` stays out of order; declared uint32 tick `4294967290→4` is a ten-tick rollover; an explicit boot-ID change starts a new epoch; an unexplained decrease reports ambiguity.
- [ ] Add `validate_time_policy`, `set_time_policy`, `get_time_policy`, `parse_timestamp` and clock-domain metadata. GUI format preview/time inspector and CLI/MCP return identical resolved/ambiguous values, precision and provenance; policy edit invalidates only dependent datasets/indexes. Run time/parser/source suites and parity, then commit.

**Acceptance:** line-axis charts cannot be labeled per second; elapsed time across unrelated boots/domains fails until an alignment is supplied. **Rollback:** disable typed time policy/index consumers, retain raw timestamp fields and ordinary field parsing. **Primary references:** [R1](https://opentelemetry.io/docs/specs/otel/logs/data-model/), [R9](https://doc.qt.io/qt-6/qtimezone.html), [D6](https://github.com/64x-lunicorn/LogSquirl/blob/a88c4a4d1c701ab1dda528a5f284ee7d43d873e1/src/logformat/include/timestampreader.h), [B1](https://github.com/dm17ryk/klogg/blob/bd74c338424845a2caac03d62fdff5187e7e8f0a/src/logdata/include/sourcelocation.h).
