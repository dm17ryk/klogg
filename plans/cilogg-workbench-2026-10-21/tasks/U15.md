# U15 — One source picker for every tool that takes a tab

**Read first:** [product specification](../00-product-spec.md), [execution guide](../MASTER_GUIDE.md),
the shared contracts in [04-workspace.md](../04-workspace.md) and the source-set contract in
[02-data.md](../02-data.md). Execute only this task or its recorded, independently reviewable slice.

**Integrated hard dependencies:** G01. Under decision [D12](../../../docs/workbench/decisions.md)
the user authorized this task ahead of G02/G03 completion on 2026-11-13, so G02/G03 are not hard
edges of U15; it uses the existing test suites and the G03 parity harness as they are. R04 depends
on U15.

**Outcome:** Value Counts, Regex Lab and every other tool that works on "a tab" lets the user choose
the source: a specific tab, a file, the focused tab, or all opened files.

**User request (2026-11-13):** "Value Counts and Regex lab should be able to choose tab/file/focused
or all opened files" and "actually each tool that uses tab, should be able to choose tab/file/focused
or all opened files". Clarified the same day (decision [D13](../../../docs/workbench/decisions.md)):
"don't limit to 8, all opened mean all".

Not tab-bound: global scripts, scenarios and suites, the Lab queue, highlighters, preview decoders,
configuration export. Current-tab tools stay on the current tab (next paragraph).

**Picker scope.** Search, filters, follow, Quick Find, encoding, save and file operations keep acting
on the current tab: they change the tab the user is looking at, and pointing them elsewhere would
change a tab the user cannot see. Automation keeps their existing Commander tab selector. Searching
several tabs at once is the explicit "search all open tabs" operation of U15b. Global settings
(highlighters, preview decoders) need no picker.

**Scheduler limits.** Analysis jobs take exactly one source (`AnalysisRequest`).
`AnalysisJobService` admits at most 10 unfinished jobs — 2 running and 8 queued — rejects an 11th
with `queue_limit`, and retains 26 finished jobs. U15 keeps these ceilings. The plan's F07 adds a real
source-set request; the selections here are designed to map onto its `SourceSelector` later.

**Slices:**

- **U15a** — a shared `SourceSelection` (`focused`, `tab:<id>`, `file:<path>`, `all`) and source
  picker widget, used by Regex Lab and Value Counts. Tabs of every window are listed.
  - `focused` is the current tab of the dock's window (with U16, of its active pane). The Run records
    that tab's id, so Apply keeps targeting it after the focus moves.
  - `all` means every open tab of every window; there is no source count limit. The dock stages the
    work (shared class `AnalysisRuns`): one job per source, in tab order; at most 8 of the Run's jobs
    are unfinished at a time, so two admission slots stay free for other tools, and a source refused
    with `queue_limit` waits for the next attempt, until every source ran. Cancel stops the running
    jobs and the sources still waiting.
  - The dock shows one source's results at a time (the user approved choosing which file's results
    to show, 2026-11-13; merged totals across sources are not part of U15a). A result-source
    selector lists every source; the status line counts the sources per state (waiting, queued,
    running, completed, failed, cancelled, or the reason a source could not start).
  - The dock keeps the jobs of the shown source and of the 16 most recently finished sources and
    releases older ones, so a large Run does not evict other tools' results. Selecting a source whose
    job was released or evicted runs it again and says so.
  - A `file:<path>` that is not open is opened in a tab first and the user runs again once it has
    loaded, so every result has a tab. Apply and Open go to the tab a result came from, in whichever
    window holds it. If that tab is closed later, Apply and Open are disabled for its results and
    refused with `source_closed`, saying why.
  - An explicit Commander tab selector (`--tab-id`, or `--window-index` with `--tab-index`) on Apply
    wins over the displayed result's source.
  - The dock definitions (`set_regex_lab`, `set_value_counts`) accept
    `source: focused|all|tab:<id>|file:<path>` and keep `sourceTabId`; the low-level analysis
    commands keep their existing tab selectors.
  - Python: the script RPC `command` method already forwards any Commander request, but the public
    `klogg` SDK exposes it only through the private `_RpcClient.command`, and has no Regex Lab or
    Value Counts call. The public route is one SDK change for every U15 consumer, so it ships with
    U15b (below); U15a's `source` values pass through it unchanged.
- **U15b** — the same picker for the consumers below. Each consumer accepts the same `source` values
  through GUI, CLI, native MCP and Python (`klogg.app.command`); an existing tab selector keeps its
  meaning and wins over `source`. Sources a tool cannot use are listed disabled with the reason.
  - Python first: U15b adds the public `klogg.app.command(action, **request)` (the same Commander
    route as CLI and MCP, as D04 requires) and `app.set_regex_lab(definition)` /
    `app.set_value_counts(definition)` with an optional `window_index`, and the parity case
    `u15_python_source_parity` (the Python fixture run through `run_script` returns the same rows as
    CLI and MCP for the U15a docks with `tab`, `file`, `focused` and `all`).

  | Plugin views | Picker in the view host's title bar; `view/opened` and later context updates carry the chosen tab | view open request `source` | `focused`, `tab`, `file` | `plugin_view_follows_chosen_tab` |

  **As implemented (U15b, 2026-11-15):**
  - One selection and one picker. `AnalysisSource` (the text grammar) moved from `analysissource.h`
    to `commander.h` (next to the new `CommanderRequest::source`) so the CLI validates `--source`
    without the UI library (`cilogg_grep` links only `klogg_commander`). `resolveAnalysisSource`
    takes `SourceRules` (`oneSource()` refuses `all` with `invalid_source`; `liveComTabs()` keeps
    COM tabs, refuses others with `not_com_tab` and files with `invalid_source`). The shared
    `populateAnalysisSourceCombo` lists refused entries disabled with the reason as tooltip, and
    `AnalysisSourcePicker` wraps it as a widget for the tools without a refresh cycle (plugin menu
    and form, view header, Script Runner, Preview). The U15a docks keep their combos (same functions).
  - CLI `--source` for `invoke_plugin`, `open_plugin_view`, `run_script`, `preview_message`,
    `search`; native MCP gets `source` from the help catalog. A `file:` path is made absolute on
    the caller's side. A refused source prints its payload (reason) on the CLI. An explicit tab
    selector wins.
  - Plugin actions: `PluginSourceRuns` (KloggApp) stages `all` with `AnalysisRuns` (8 unfinished,
    a full plugin manager answers `queue_limit` and the tab waits). The GUI picker is
    **Plugins → Run actions on** (a widget in the menu) and a **Run on** row in an action's form.
  - Plugin views: the picker is a **Source** row at the top of the view (the dock's own title bar
    keeps its float and close buttons). Choosing a source re-sends `view/opened` with that tab's
    context (protocol unchanged); buttons run on that tab. New Commander action
    `open_plugin_view --plugin-id --view-id [--source]` (the E13 limitation "no command opens a
    view"); `view/show` accepts `source`.
  - Preview: **Source**, **Line** and **Preview line** at the top of the Preview window.
  - Search: **All Tabs** toggle of the search line; `search --source all [--wait]` returns
    per-tab `matches` and `complete`; the GUI shows the total on the search line, per-tab counts in
    its tooltip.
  - Actions, responses, COM controls: the Actions window's "Action tabs" list already offers only
    COM tabs that can send actions (most recently used first) and stays as it is; COM controls keep
    their Commander tab selectors. `com_tools_list_only_com_tabs` checks that, the window's
    `sourceType`, and the COM rule of the shared picker.
  - Commander transport: on Windows the single-instance sender could report a failed send
    although the primary had read the message (about 1 send in 75 in a stress probe). The command
    message now carries a `receiptPath`; the primary writes the receipt on arrival, and the sender
    waits for it only after a reported failure (no re-send, so no command runs twice).
  - Python: `klogg.app.command(action, **request)` takes the CLI / native MCP argument names;
    `app.set_regex_lab` / `app.set_value_counts`. The parity fixtures run through
    `run_global_script`: the private parity host has no COM tab, so `run_script` cannot run there.
