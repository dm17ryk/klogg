# U15 — One source picker for every tool that takes a tab

**Read first:** [product specification](../00-product-spec.md), [execution guide](../MASTER_GUIDE.md),
the shared contracts in [04-workspace.md](../04-workspace.md) and the source-set contract in
[02-data.md](../02-data.md). Execute only this task or its recorded, independently reviewable slice.

**Integrated hard dependencies:** G01. Under decision [D12](../../../docs/workbench/decisions.md)
the user authorized this task ahead of G02/G03 completion on 2026-11-13, so G02/G03 are not hard
edges of U15; it uses the existing test suites and the G03 parity harness as they are. R04 depends
on U15.

**Outcome:** Value Counts, Regex Lab and every other tool that works on "a tab" lets the user choose
the source: a specific tab, a file, the focused tab, or all opened files.

**User request (2026-11-13):** "Value Counts and Regex lab should be able to choose tab/file/focused
or all opened files" and "actually each tool that uses tab, should be able to choose tab/file/focused
or all opened files". Clarified the same day (decision [D13](../../../docs/workbench/decisions.md)):
"don't limit to 8, all opened mean all".

**Inventory (2026-11-13, master `76542bb3`):**

| Tool | Source today | U15 |
|---|---|---|
| Regex Lab, Value Counts | Own, duplicated combo: "current tab at Run", the tabs of this window, a closed source, pasted text. Apply always targets the current tab. | U15a |
| Analysis CLI (`regex_evaluate`, `value_counts`, Regex Lab / Value Counts commands) | `--tab-id`, or `--window-index` with `--tab-index`, else the focused tab | U15a (dock definitions); low-level selectors unchanged |

| Search, filters, follow, Quick Find, encoding, save, file operations | The current tab, or the Commander tab selector | Stay current-tab by design |
| Actions window, responses, COM controls | COM tabs only, picked by MRU or the Commander tab selector | COM-tab picker (U15b) |

**Picker scope.** Search, filters, follow, Quick Find, encoding, save and file operations keep acting
on the current tab: they change the tab the user is looking at, and pointing them elsewhere would
change a tab the user cannot see. Automation keeps their existing Commander tab selector. Searching
several tabs at once is the explicit "search all open tabs" operation of U15b. Global settings
(highlighters, preview decoders) need no picker.

**Scheduler limits.** Analysis jobs take exactly one source (`AnalysisRequest`).
`AnalysisJobService` admits at most 10 unfinished jobs — 2 running and 8 queued — rejects an 11th
with `queue_limit`, and retains 26 finished jobs. U15 keeps these ceilings. The plan's F07 adds a real
source-set request; the selections here are designed to map onto its `SourceSelector` later.

**Slices:**

- **U15a** — a shared `SourceSelection` (`focused`, `tab:<id>`, `file:<path>`, `all`) and source
  picker widget, used by Regex Lab and Value Counts. Tabs of every window are listed.
  - `focused` is the current tab of the active window (with U16, of its active pane).
  - `all` means every open tab of every window; there is no source count limit. The dock stages the
    work: one job per source, submitted while the service admits it; on `queue_limit` it waits for one
    of its own jobs to finish and submits the next, until every source ran. Cancel stops the running
    jobs and the sources not yet submitted.
  - The dock keeps a per-source summary (source, state: waiting / running / done / failed /
    cancelled, match or value counts), so merged Value Counts totals and the Regex Lab grouping do not
    depend on retained jobs. When the user selects a source whose finished job the service has
    evicted, the dock re-runs that source and says so.
  - Regex Lab groups results by source; Value Counts merges counts with a per-source breakdown.
  - A `file:<path>` that is not open is opened in a tab before its job runs, so every result has a
    tab. Apply and Open go to the tab a result came from, in whichever window holds it. If that tab is
    closed later, Apply and Open are disabled for its results and say why.
  - An explicit Commander tab selector (`--tab-id`, or `--window-index` with `--tab-index`) on Apply
    wins over the displayed result's source.
  - The dock definitions (`set_regex_lab`, `set_value_counts`) accept
    `source: focused|all|tab:<id>|file:<path>` and keep `sourceTabId`; the low-level analysis
    commands keep their existing tab selectors.
  - Python: the script RPC `command` method already forwards any Commander request, but the public
    `klogg` SDK exposes it only through the private `_RpcClient.command`, and has no Regex Lab or
    Value Counts call. U15a adds the public `klogg.app.command(action, **request)` (the same
    Commander route as CLI and MCP, as D04 requires) and `app.set_regex_lab(definition)` /
    `app.set_value_counts(definition)` with an optional `window_index`, passing `source` unchanged.
- **U15b** — the same picker for the consumers below. Each consumer accepts the same `source` values
  through GUI, CLI, native MCP and Python (`klogg.app.command`); an existing tab selector keeps its
  meaning and wins over `source`. Sources a tool cannot use are listed disabled with the reason.

  | Consumer | GUI | CLI / native MCP | Sources | Acceptance case |
  |---|---|---|---|---|
  | Plugin actions | Picker in the plugin action menu and dialog | `invoke_plugin --source …` | all four; `all` invokes once per tab, staged like U15a | `plugin_action_on_each_source` |
  | Plugin views | Picker in the view host's title bar; `view/opened` and later context updates carry the chosen tab | view open request `source` | `focused`, `tab`, `file` | `plugin_view_follows_chosen_tab` |
  | Script Runner | Picker beside Run; rerun/stop keep the run's tab | `run_script --source …` | COM tabs: `focused`, `tab`, `all` (one run per COM tab); `file` disabled, a script needs a live session | `script_runner_on_chosen_com_tabs` |
  | Preview | Picker in the Preview window | `preview_message --source … --line N` | `focused`, `tab`, `file`; `all` is rejected with `invalid_source`, a line number names one source | `preview_line_from_chosen_source` |
  | Search all open tabs | "In all open tabs" option of the search line | `search --source all` (also `tab`, `file`) | all four; each tab's filtered view runs the search; the result lists per-tab match counts | `search_all_open_tabs` |
  | Actions, responses, COM controls | COM-tab picker | existing tab selectors | COM tabs only | `com_tools_list_only_com_tabs` |

**Acceptance:** U15a: Regex Lab and Value Counts run on a chosen tab of any window, a file (opened in a
tab first), the focused tab or every open tab from GUI, CLI, native MCP and Python; more sources than
the scheduler admits are staged and all of them run; results say which source they came from;
Apply and Open reach that source's tab; nothing is silently skipped. U15b: every consumer in its table
passes its acceptance case through GUI, CLI, native MCP and Python; current-tab tools behave as
today.

**Rollback:** The picker falls back to "focused tab"; existing tab selectors keep working; the new
Python calls can be removed without affecting existing scripts.
