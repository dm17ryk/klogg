# UT02a — Read-only terminal attachment Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans for implementation. Keep a per-task ledger, observe behavioral RED/GREEN tests and obtain whole-branch C++ and general review before publication.

**Goal:** Attach the existing bounded terminal emulator to raw RX from the checked serial owner and make its read-only screen available in the connected session window, Commander, CLI, native MCP and Python together.

**Architecture:** StreamSession remains the session/policy/publication owner. SerialCaptureWorker remains the sole serial-device and capture-file owner. TerminalController owns presentation state only, on the session thread. It cannot open a device, transmit bytes, change capture settings or manufacture canonical event provenance.

**Tech Stack:** C++17, existing Qt5/Qt6 compatibility, pinned libvterm/model, Catch2/QtTest and existing Commander/MCP parity harnesses.

**Spec:** [terminal contract](../11-unified-terminal.md), [UT02](../tasks/UT02.md), [UT01a](UT01a-terminal-model.md), [D01c](D01c-existing-owner-adapter.md), [ownership baseline](../../../docs/workbench/ut00-terminal-baseline.md).

## Runtime contract

- Attachment is explicit, runtime-only and starts at the current RX position; it does not replay decorated capture text or promise earlier history. Opening/closed/file-only targets return a structured reason rather than implicitly starting a connection. Repeating attachment to the same active epoch is idempotent.
- Every delivery and snapshot carries an opaque attachment ID, the existing endpoint ID and connection generation. RX offsets are attachment-local byte offsets, explicitly labelled noncanonical; terminal cell coordinates never become physical log lines or EventRefs. Formal UT02 later supplies canonical EventRecord/EventRef mapping and transcript acceptance.
- Check current epoch before queue admission, feed, timer continuation and publication. Disconnect freezes the last screen as historical and stops consumption. Reconnect begins a fresh attachment epoch with a reset model; stale queued deliveries, replies and pages cannot affect it. Release detaches presentation and cancels scheduled work without closing the session.
- Bound terminal RX retention to 8 MiB and each delivered chunk to 64 KiB, including both pending and currently consumed bytes; count retained allocations rather than only logical sizes. One terminal-specific payload delivery may be in flight. Process at most one model quantum per continuation. Coalesce screen-change notifications to one pending notification; slow/hidden consumers do not accumulate full-screen snapshots.
- If an exact terminal projection cannot continue within its bound, mark it incomplete with `resource_limit`, freeze the last valid screen and stop admitting terminal RX. Keep capture and the serial connection usable. Report counters and the lost coverage interval; never silently drop bytes and continue displaying the projection as complete.
- Default dimensions remain 80×24. Validate dimensions against existing model caps before allocation. Public pages default to 200 cells and never exceed 16,384 cells or a separately enforced encoded-byte cap of 1 MiB. Reject one-over requests; do not silently clamp them. Define UTF-16 cell text and zero-based terminal coordinates explicitly.
- A snapshot page is immutable and revision-bound. Subsequent pages require attachment ID, connection generation and model revision; stale revisions return `stale_revision`. Revision and generation identifiers use lossless representations over JSON. Validate integer ranges before narrowing, including malformed/fractional/negative JSON values.
- No input/reply route is enabled. Device queries may generate emulator replies, but inspection discards them, counts them and visibly reports suppression. Never echo private TX into the emulator. Do not imply that RX cannot contain secrets echoed by a device.
- Automated mode/resize mutations require an explicit runtime-only, per-session presentation-control permission. It defaults false and is revoked on detach, close or generation change. Add `set_terminal_automation_permission` with required explicit endpoint/current-generation and enabled boolean across GUI/CLI/native-MCP/Python. This deliberate opt-in operation is evaluated within the existing local Commander trust boundary; neither saved state, Actions flags, a mode request nor a restored/replayed scenario implicitly grants it. This permission permits presentation changes only, never input, transport control or process launch. Future input has its own full authorization/arming gate.
- Diagnostics contain bounded IDs, generations, offsets, queue/credit counts, revisions, resource decisions and static reasons. Omit bodies and hashes/hex/base64 of bodies. Report model failures explicitly; do not swallow them into a successful screen response.

## Interfaces shared by the tasks

These are proposed private attachment types, not another endpoint, EventRef or receipt codec. Reuse `cilogg::communication::WriteEpoch` for endpoint identity/generation and `terminal::Result`, `Size` and `Snapshot` from the existing model.

- `TerminalAttachmentState`: epoch, opaque `QString attachmentId`, revision, dimensions, lifecycle (`detached`, `attaching`, `attached`, `historical`, `failed`), `bool complete`, `QString reason`, attachment-local admitted/consumed byte counters, retained bytes/chunks and suppressed reply bytes. Counters are checked `quint64`; overflow fails the projection before wrapping. Completeness applies only to the explicitly labelled attachment coverage, never earlier connection history. Publish `attached` only after a current-epoch worker acknowledgment establishes the RX cut.
- `TerminalRxDelivery`: epoch, attachment ID, monotonically increasing sequence, attachment-local start offset and private `QByteArray bytes` of at most 64 KiB. The worker owns at most 256 retained chunks and 8 MiB, including in-flight data. A controller borrows the immutable in-flight delivery rather than duplicating full bodies. Tiny chunk floods hit the chunk cap explicitly.
- `TerminalAdvance`: `Result result`, `std::optional<quint64> acknowledgedSequence`, `bool needsContinuation`, and `quint64 discardedReplyBytes`. `TerminalController(WriteEpoch, QString attachmentId, Size)`; `Result accept(QSharedPointer<const TerminalRxDelivery>)`; `TerminalAdvance advance()`; `void close(const WriteEpoch&)`; `TerminalAttachmentState state() const`; `Snapshot snapshot(int firstCell, int count, quint64 expectedRevision) const`. Accept validates epoch, ID, contiguous offset, sequence and credit before retention. Advance consumes at most one existing model quantum and returns a completion acknowledgment only after the delivery is fully consumed or the projection has failed. Failed acceptance consumes no bytes.
- In new private `src/ui/include/serialreadbridge.h` and `src/ui/src/serialcapturereader.cpp`, worker methods `attachTerminalRx(const WriteEpoch&, const QString&)`, `acknowledgeTerminalRx(const WriteEpoch&, const QString&, quint64 sequence)` and `detachTerminalRx(const WriteEpoch&, const QString&)` manage one attachment and credit. Add `publishTerminalRx(const QByteArray&)` at `SerialCaptureWorker::onReadyRead` before the existing `dataReceived` emission, without changing capture formatting. One metadata-only overflow/error notification is latched; no unlimited error queue.
- `StreamSession` owns the optional controller and exposes presentation-only state/page/resize methods. Attach uses the checked owner's existing endpoint ID and worker generation. Add a private `acceptTerminalRx` slot and one scheduled `advanceTerminalRx` continuation; acknowledge the worker before publishing a public screen-change notification. Emit immutable IDs/revisions only, never another queued copy of the screen/body.
- `StreamSession::setTerminalAutomationPermission(const WriteEpoch&, bool) -> Result` changes the runtime-only display grant on a current open session and returns a structured rejection for stale/closed epochs. Store no grant in settings. `TerminalAttachmentState`/state responses expose the effective grant separately from lifecycle, mode and Actions/Responses. Manual GUI operations carry an internal invocation origin set by the GUI dispatcher, never a caller-serializable bypass field. Automated mode/resize routes enforce the grant; the explicit grant/revoke operation itself does not require a preexisting grant.
- `MainWindow::commanderTerminal(const CommanderRequest&) -> CommanderResult` in new `src/ui/src/mainwindowterminal.cpp` resolves the existing target session and calls those checked presentation methods. Add typed presentation request fields to `CommanderRequest` and lossless conversions in `commander.cpp`; do not overload unrelated analysis/text fields.
- `isCommanderTerminalAction(CommanderAction) -> bool` in the shared Commander contract identifies these five operations for routing and transport. Terminal errors use the existing `CommanderResult` envelope with a structured payload carrying stable reason and available attachment/state metadata. Required reasons include `permission_denied`, `stale_generation`, `stale_revision`, `resource_limit`, `feature_disabled` and `invalid_request`. Preserve this payload on CLI failure exits in `src/app/main.cpp` and native-MCP failure handling in `src/app/mcp/runtime.cpp`; their current structured-failure exceptions cover analysis only. Extend the supported structured-error path explicitly without classifying terminal actions as analysis. Native MCP retains error signalling plus the parseable result envelope; keep existing nonterminal behavior unchanged.
- `TerminalScreenView` in the same session content area reads pages through the same command/service, retains only the current bounded screen, and schedules at most one redraw. Stable names: `terminalScreenView`, `terminalPresentationSelector`, `terminalInspectionStatus`. Accessible names: `Terminal screen`, `Session presentation`, `Terminal inspection status`.
- Public modes are `log` and `inspect`. Mode changes/resizes require explicit endpoint ID/current generation; automated calls additionally require the presentation grant above. GUI actions are bound to the same immutable target and use the same checked service/semantic commands. These presentation-only mutations grant no input/process/transport authority; endpoint IDs/generations are stale-work fences, not authentication credentials.

## Review focus

- Saturated control/query streams must not fill a hidden reply queue or write to the endpoint; Task 1 tests reply suppression and Task 2 asserts zero backend writes.
- A tiny-chunk flood must obey both allocation-count and byte caps; Task 1 tests 256 chunks and one-over while the receiver stalls.
- A tab/observer may delete or restart the session during publication; Task 2 proves no use-after-free and no old-generation screen update.
- An application consumer must build with tests disabled and both feature gates ON; Task 4 validates that configuration and the gate-OFF MOC path.
- Screen paging may race continuous RX or exceed exact JSON integer precision; Task 3 proves explicit stale-page failure and lossless identifier round trips.
- Session restoration/reconnect must never inherit automation permission; Tasks 2 and 3 test default-denied mutations, explicit grant, revocation/reset and attempts to spoof a manual origin.
