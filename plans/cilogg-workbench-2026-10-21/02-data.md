# CILogg General Event, Field, Time, and Query Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give every logger, table, chart, dashboard, export, and automation operation one bounded, source-linked interpretation of events, fields, time, queries, and aggregate datasets.

**Architecture:** Keep `AnalysisJobService` as the sole admission, scheduling, cancellation, pagination, expiry, and retained-result authority. Add common typed contracts to `klogg_logdata`, parsers to new `klogg_logformat`, and query/dataset orchestration to new `klogg_analysis`; widgets consume these services. Preserve the existing physical-line search and accelerated regex paths, and use the existing supervised capture worker wherever arbitrary regex evaluation promises a deadline.

**Tech stack:** Existing C++17, Qt5/Qt6, Catch2/Qt Test, `AnalysisJobService`, `SourceSnapshot`/`SourceLocation`, Commander, native MCP, current encoding and file watchers; optional compressed-input libraries only after inspecting the currently packaged KArchive capabilities.

**Spec:** The requested developer logger/visualizer/automation expansion; `plans/log-analysis-roadmap.md`, especially P06–P14 and P22–P23. This section extends the roadmap's initial one-line-per-record scope deliberately: F04 makes multiline grouping optional and source mapped; F06/F07 make chronological merge an explicit operation after clock policy exists.

## Global constraints and common acceptance contract

- Keep C++17 and Qt5/Qt6 compatibility. Donor code uses different assumptions, including C++20 constructs; adapt behavior instead of copying interfaces blindly.
- Raw capture/source bytes remain authoritative and unmodified. ANSI, Value Names, display formatting, unit labels, alignment, and derived formulas remain separate layers.
- Internal physical lines are zero based; public `lineNumber` values are one based; character spans are UTF-16 code units in decoded raw text before display transforms. Raw byte ranges are half-open and measured from the original source, including a separately represented terminator.
- Preserve the current scheduler ceilings: two running and eight additional admitted jobs; 256 physical lines / 1 MiB raw per block; 1 MiB physical record; eight pending batches / 4 MiB pending bytes per job; 10,000 retained rows / 16 MiB per job; 64 MiB globally; 4 MiB serialized row; pages default 200, maximum 1,000, maximum 8 MiB; at most 26 retained jobs, ten-minute expiry; 60-second default / ten-minute maximum deadline. New parser, group, window, cache, or disk caps are independent accounted budgets, never an excuse to bypass existing caps.
- Proposed initial configurable data ceilings: 256 fields/event, JSON/XML nesting depth 32, 256 physical lines and 1 MiB decoded UTF-8/event, 64 simultaneously selected open sources, 10,000 frozen folder manifest entries, 10,000 group keys, 10,000 buckets/cells, 64 output columns, 32 MiB parsed-event cache and 16 MiB active-query state globally. Treat these as explicit starting defaults to measure in P00, not measured performance claims. A caller can lower them. Higher values require a separately validated configured maximum.
- Values have a tagged wire format. Signed/unsigned 64-bit numbers, exact decimals, counters, revisions, durations, and timestamp components use decimal strings where JSON would lose precision. A field never becomes numeric zero merely because conversion failed.
- Unknown/ambiguous time and clock quality remain visible. A missing timezone never silently becomes UTC. Uptime, observed host time, file modification time, ingestion/read time, and event wall time are distinct roles.
- Exact operations stop with an explicit limit or partial reason. Approximation is opt-in, versioned, and labeled with algorithm/parameters; it is never substituted for exact results. A capped prefix is not labeled an all-source sort, completed distribution, or true top-N.
- GUI, CLI, Python Commander callers, and native MCP use the same versioned operations. CLI shape is `cilogg command --action ACTION --json-file request.json`; MCP shape is `cilogg_execute` with `{"action":"ACTION","arguments":{"analysis_json":REQUEST}}`, using the current catalog conventions. All long operations return the existing analysis job ID; poll `get_analysis_job`, page `get_analysis_results`, and use existing cancel/release. New action names below are proposed catalog additions, not claims of current availability.
- Data provenance includes source manifest/generation/revision/watermark, request revision, parser/profile revision, assembly policy revision, time/alignment policy revision, query revision, lookup revisions, completion/reason, and exact/approximate state. Routine diagnostics include IDs/counters/branch reasons, not log bodies or lookup contents.
- Register focused Catch2 cases under `[data][Fxx]`; UI integration cases also use `[ui]` or `[logdata]` as required by the existing Windows test split. Each card follows: write its stated failing cases; implement only that card; run its focused cases; run relevant existing regression suites and parity; document measured evidence and clean rollback; commit a focused change. No product compilation/runtime verification was performed merely by writing this plan.
- At implementation time, reread the current checkout's `AGENTS.md`, refresh any stale GitNexus index, run upstream `gitnexus_impact` before changing each symbol, report direct callers/affected processes/risk and any HIGH/CRITICAL result, and run `gitnexus_detect_changes` before committing. If an index/tool is unavailable, record that limitation and use pinned direct source/caller evidence; do not claim graph verification. This planning task used direct pinned source reads and does not claim a fresh local graph index.

**Required verification commands at execution time:** use the repository's clean VS2022 environment and `scripts/codex/build-windows.ps1 -Config RelWithDebInfo`, then `scripts/codex/run-tests.ps1 -Config RelWithDebInfo`. The real CMake switch is `KLOGG_BUILD_TESTS`. Focused examples are `cilogg_tests.exe '[data][F01]' -platform offscreen` and `cilogg_itests.exe '[data][F07]' -platform offscreen`. ## Shared proposed contracts

### Types fixed before consumers land

`src/logdata/include/{fieldvalue,eventrecord,datasetschema,queryspec}.h` owns common contracts only. It depends on existing Core/source-location types and has no dependency on parser/UI code. All records and definitions are immutable values or immutable shared handles after publication.

| Type | Required members / semantics |
|---|---|
| `DataError` / `DataResult<T>` / `DataStatus` | `DataError{QString code,message,fieldId; std::optional<SourceLocation> location;}`; `DataResult<T>{std::optional<T> value; DataError error;}`. Exactly one of a value or nonempty error code is returned. Void operations use `DataStatus{bool ok;DataError error;}`, not `std::optional<void>`. |
| `RawByteRange` | `quint64 begin,endExclusive`; checked arithmetic; absent for inline text or when exact raw mapping is unavailable. Byte ranges are obtained from the indexed reader, never from `QString::size()` or UTF-8 re-encoding. |
| `FieldType` / `FieldValue` | `FieldValue{FieldType tag;ValuePayload payload;std::optional<QString> rawLexeme;}`; payload is a C++17 variant checked against its tag. Tags: `Missing,Null,Bool,Int64,UInt64,Decimal,Float64,String,Bytes,Timestamp,Duration,Array,Object,Invalid`. `DecimalValue{QString coefficient; qint32 scale;}` means coefficient × 10^-scale, with canonical signed integer coefficient; bound coefficient length to 256 digits and scale to [-6144,6144]. Container nodes are bounded immutable shared nodes. Invalid carries raw lexeme + conversion reason. Float values are finite unless a profile explicitly preserves a nonfinite token as Invalid. |
| `FieldSchema` | `QString fieldId,name,path,unit; FieldType type; bool nullable,repeated; QString semanticRole;` plus profile revision and optional enum/lookup binding. Stable `fieldId` is separate from visible column name. |
| `FieldOrigin` | Either original `EventRef` + optional real physical line/UTF-16 span(s) or managed-byte span(s), or a versioned derived expression/lookup with input `FieldId`s and `LineageHandle`; absent spans stay absent. A JSON-escaped string or multiline field may map to several raw spans. Byte-only managed/HID frames do not acquire fabricated text/line anchors. |
| `EventOrigin` / `EventRef` | `using EventOrigin=std::variant<PhysicalEventOrigin,InlineEventOrigin,DeferredFileOrigin,ManagedByteOrigin>; EventRef{QString eventKey;EventOrigin origin;QString formatId;quint64 formatRevision,assemblyRevision,occurrenceOrdinal;}`. The discriminated origin is exactly one alternative; wire decoding rejects zero/multiple/unknown alternatives. An explicit exploded record gets its own occurrence ordinal. Keys derive from the chosen origin identity + event start/range + assembly revision, never a table row number. |
| `PhysicalEventOrigin` | `SourceLocation first,last;std::optional<RawByteRange> bytes;`. Both locations belong to one real open source generation and are obtained through its current `SourceSnapshot::location`; validate both, especially a provisional final location. This preserves every existing raw-file lifetime/revision rule. |
| `InlineEventOrigin` | `QString inlineSourceId;quint64 firstLine,lastLine;`. Identifies the immutable inline text job input. It has no navigable `SourceLocation`; byte ranges are absent unless a separate explicitly managed backing exists. |
| `DeferredFileOrigin` | `QString manifestId,entryId;quint64 manifestRevision,contentEpoch;quint64 firstLine,lastLine;std::optional<RawByteRange> bytes;`. Line/byte ranges are the values observed during the folder scan, not a claim that a `LogData` is still open. The referenced manifest entry owns immutable `DeferredSourceVerification` and encoding/assembly policy. F16 supplies checked materialization; until then resolve returns `deferred_resolution_required`/`unsupported_source_kind`. |
| `ManagedByteOrigin` | `QString resolverKind,recordingId,segmentId;quint64 generation;RawByteRange bytes;`. Offsets are segment-relative half-open ranges and serialize as decimal strings; recording/segment IDs are opaque and generation is an equality epoch. D01 registers `resolverKind="communication"`; its immutable retained-segment descriptor owns byte length/content hash, and its ClockStamp carries clock origin/resolution/uncertainty separately. Event keys include recording/segment/generation/range/occurrence. No physical line/UTF-16 anchor is invented. F01 defines/codecs this generic contract without depending on D01; absent/expired/mismatching backing returns an error, never replacement bytes. |
| `DeferredSourceVerification` | `FileIdentitySnapshot identity;quint64 frozenBytes,completeLineCount;std::optional<quint64> provisionalLineStart;QByteArray sha256Prefix;std::optional<RetainedBackingHandle> backing;QString encoding;quint64 decodingRevision;`. `FileIdentitySnapshot` records canonical origin/member, platform volume/file ID when available, captured size and modification/change metadata. Deferred rebinding requires a matching strong SHA-256 digest of the exact frozen byte prefix or a validated immutable retained backing; metadata/sampled hashes alone are insufficient. A source exceeding a verification budget returns `verification_limit`, never a guessed location. |
| `EventRecord` | `EventRef ref; QVector<FieldValue> values; QVector<FieldOrigin> origins; QString parseStatus; QVector<DataError> diagnostics;` with a shared field schema handle. Message/raw body is a field/reference, not a second rewritten source. |
| `TimeValue` | Tagged `UnixInstant{qint64 seconds;quint32 nanos;}`, `LocalCivil{date,time,zone/offset status,fold}`, or `Uptime{quint64 ticks;quint64 ticksPerSecond;QString bootId;}`; `QString clockDomain`, original lexeme, precision digits, optional written offset, quality, and time-policy revision. No global `double milliseconds` representation. |
| `SourceManifestEntry` | Stable `manifestId,entryId,manifestRevision,contentEpoch` + origin path/member/device/capture identity, encoding, parser/clock revisions, availability and per-source error. An open-source entry additionally has its real optional `SourceSnapshot` UUID/generation/revision/watermark/line/provisional metadata. A deferred file has `DeferredSourceVerification` instead of a fabricated/reused open UUID; a managed recording has its segment/backing identity. Entries do not pin 10,000 open readers or claim a filesystem snapshot when only watermarks are frozen. |
| `DatasetColumn` / `DatasetSchema` | Column `fieldId,name,type,unit,semanticRole,clockDomain,nullable,repeated`; schema `quint32 schemaVersion; QVector<DatasetColumn> columns; QString shape;` and versioned shape metadata. Schema roles include dimension, measure, time, source, event, lower/upper bound, count, numerator, denominator, duration, hierarchy path, edge source/target, and lineage. |
| `DatasetRow` | `QString rowId; QVector<FieldValue> values; LineageHandle lineage;` row IDs are opaque and stable within a published dataset revision. |
| `LineageHandle` | Opaque job ID + dataset revision + row ID token. Server retains a bounded normalized predicate/transform selector against the frozen source manifest, not an unbounded list of contributing events. |
| `QuerySpec` | Versioned AST: `quint32 schemaVersion; QVector<QueryStage> stages; QString queryId; quint64 revision;` where stage is a tagged filter/project/extend/group/order/window/pivot/top/limit/transform node. Field references use stable IDs; typed literals use `FieldValue`; no embedded JavaScript, SQL, shell, or arbitrary callback. Each stage has a stable stage ID and typed output contract. |
| `DatasetRequest` | `quint32 schemaVersion; SourceSetHandle sourceSet; DatasetScope scope; AnalysisLimits limits; DataLimits dataLimits; quint64 requestRevision; LivePolicy live;` plus immutable selected profile/time/lookup bindings. Scope explicitly chooses sample/selection/current completed matches/whole source/source set/time range/text and physical-line versus assembled-event semantics. |
| `DatasetDescriptor` / `AggregateDataset` | Retained metadata: `jobId,datasetRevision,requestRevision,schema,sourceManifest,queryHash,state,completion/reason,exactness,coverage,metrics,DataError error`; `AggregateDataset` adds aggregate definitions/group/bucket/denominator/algorithm metadata and remains a handle, not a full `QVector` of data. Unknown/expired job sets error rather than returning an apparently empty successful dataset. |
| `DatasetPage` | `jobId,datasetRevision,requestRevision,rows,nextCursor,state,complete,reason,sourceManifestRevision,historical,newerDataAvailable,DataError error`; schema is supplied on the first page and by `describe`. Each page belongs entirely to one revision. Invalid/stale revision cursor returns `stale_cursor`; it never mixes two live revisions. |

### Service API consumed by visualizations and automation

Create `src/analysis/include/analysisdatasetservice.h` with the following proposed signatures. `klogg_analysis` links `klogg_logformat` and `klogg_logdata`; `klogg_logformat` links `klogg_logdata`; widgets link `klogg_analysis`. Add `src/logformat` then `src/analysis` after `logdata` in `src/CMakeLists.txt`. There must be no `logdata` → `logformat` dependency cycle.

```cpp
class AnalysisDatasetService : public QObject {
    Q_OBJECT
public:
    explicit AnalysisDatasetService(AnalysisJobService& jobs, QObject* parent = nullptr);
    DataResult<SourceSetHandle> freezeSources(const QVector<SourceSelector>& selectors,
                                            const DatasetScope& scope);
    QString submit(QuerySpec query, DatasetRequest request, QString* error = nullptr);
    DatasetDescriptor describe(const QString& jobId) const;
    DatasetPage page(const QString& jobId, const QString& cursor = {}, int pageSize = 200);
    QString drilldown(const QString& jobId, const LineageHandle& lineage,
                      const DrilldownRequest& request, QString* error = nullptr);
    DataResult<ResolvedEvent> resolve(const EventRef& event) const;
    QString materialize(const EventRef& event, const ResolvePolicy& policy,
                        QString* error = nullptr);
    DataStatus registerOriginResolver(const QString& resolverKind,
                                      OriginResolverFactory factory);
    DataResult<LiveSubscription> subscribe(QuerySpec query, DatasetRequest request);
    bool detach(const QString& subscriptionId);
Q_SIGNALS:
    void datasetChanged(const QString& jobId, quint64 datasetRevision);
};
```

`SourceSelector` is a tagged `openTabUuid`, `inlineText`, `folderManifestHandle`, or registered `managedRecording` selector; `SourceSetHandle` is an immutable shared manifest with bounded reader factories/leases, not one lease per unopened file. `DatasetScope` contains scope tag + physical ranges/event closure/time bounds and explicitly reports scope expansion; `DrilldownRequest` contains `mode=events|context|matchingRanges`, page/row bounds and optional additional typed filter. `ResolvedEvent` returns the original EventRef, validated current source/tab/origin, physical ranges/raw spans when real, optional newly materialized physical EventRef, and verification/binding revision. `ResolvePolicy` fixes strong-prefix/retained-backing verification, maximum verification bytes/deadline, and current-versus-historical navigation mode. `resolve` is a bounded check of an existing current binding; `materialize` is a normal asynchronous analysis job for file/hash/open/index work, never a GUI-thread whole-file re-read. `OriginResolverFactory` makes a provider that checks an existing binding and returns a normal-job materialization plan for its origin kind; F07 owns this basic registry/API and `materialize_dataset_event` route, so F16 does not acquire a hidden dependency on F10's later aggregate lineage/inspector work. `LiveSubscription{QString subscriptionId,jobId;quint64 datasetRevision;}` exposes the latest bounded execution epoch. F16 owns the actual recursive folder engine/readers/navigation adapter; F07 can reject folder selectors until F16 registers that capability. D01 separately registers managed-byte backing capability; neither adds a dependency to F01.

`submit` and drilldown return normal `AnalysisJobService` job IDs; `page` decodes the typed envelope already retained by that service. Cancel/release/status stay on existing operations. An optional UI adapter named `ChartDatasetAdapter` is a thin consumer of this API. It does not parse, reduce, maintain another job queue, or calculate missing buckets in JavaScript.

**Early P06 path without the structured/time stack:** F01 compiles in `klogg_logdata` alone. Initial numeric-versus-physical-line charts can call the current `AnalysisJobService::start` with `makeRegexProcessor`, then use proposed pure functions `DataResult<DatasetDescriptor> describeCaptureDataset(const QVariantMap& jobStatus,const CaptureDatasetSpec&); DataResult<DatasetPage> decodeCaptureDatasetPage(const QVariantMap& page,const CaptureDatasetSpec&);` in `src/logdata/include/capturedatasetadapter.h` / `src/logdata/src/capturedatasetadapter.cpp`. `CaptureDatasetSpec` fixes selected subpattern/captures, exact numeric conversion/unit, physical-line X role and request revision. These functions only translate existing retained result pages into the F01 typed shape; navigation uses existing `AnalysisJobService::location`, and submission/paging/cancel/release use existing operations. They introduce no parser target, query scheduler or `klogg_analysis` dependency. F07 later replaces the submission adapter with `AnalysisDatasetService`; F11 adds compatible scan sharing/live execution. Neither is a prerequisite for the first P06 charts.

The reader streams ordinary files without constructing a persistent full line index. It preserves BOM/forced encoding precedence, decoder state across chunks, exact original byte offsets, raw LF/CRLF/final-line rules and physical UTF-16 spans. It uses the same 256-line/1MiB block and 1MiB physical-record limits and the same matcher/capture-worker budgets as open sources. Oversized/malformed/short-read inputs produce a named per-file outcome; no padded bytes or guessed offsets are exposed. A query freezes each file's read watermark/content epoch when it is admitted; discovery is not an atomic filesystem-wide snapshot. Directory discovery and file scans overlap within one ordinary admitted pipeline so early file results arrive before all files are scanned; its growing manifest is explicitly `building`, then sealed or marked partial. Only sealed immutable manifest revisions may be reused by a later `freezeSources(folderManifestHandle)`. Previously published pages identify their exact manifest revision; no page silently changes file identity. All work uses the current analysis scheduler and bounded credits, not a second worker pool or unbounded file-result queue.

**Deferred identity/materialization:** never create a SourceSnapshot/SourceLocation for a directory entry that has no real open LogData. A `DeferredFileOrigin` points to the manifest entry and its observed line/byte ranges. During scanning, capture platform identity/size/change metadata, the exact consumed-prefix SHA-256 and final/provisional boundaries; retain hits only within accounted query-state/pending limits until their verification descriptor is finalized. Optionally retain immutable raw backing under an explicit default256MiB/job and512MiB global backing quota; no policy pins every file or all readers. Once a file is processed its OS reader can close; all10,000 manifest entries remain metadata only. File replacement/deletion/closure between results and navigation is therefore expected, not a reason to retain10,000 open LogData instances.

F07's `resolve` checks an existing verified binding quickly; otherwise its `materialize_dataset_event` route calls F16's normal cancellable job. If bytes changed, return `stale_source` and offer an explicit new search against current content. A retained old backing can open historical context clearly labeled with the original manifest; it cannot claim to be the current source. Verification over its configured bytes/deadline returns `verification_limit`/timeout. The old deferred reference is retained unchanged and is never relabeled as a new SourceLocation.
